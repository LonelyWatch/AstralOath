# Arena

模拟战目录、创建房间弹窗和房间页由独立 View/Binder 管理。目录用 ScrollRect 支持鼠标滚轮与触屏拖动。更新目录从服务端查询，可按公开状态、人数、最近创建和房名筛选。创建房名最多 28 字，支持四位数字密码、聊天开关、五个规则选项。规则目前随房间保存，房间页尚未接入开战。点击开始会播放禁止音并提示具体原因。

房间 Binder 使用独立生命周期并行读取成员和聊天。成员请求每 5 秒刷新在场状态。聊天使用最多 8 秒的长轮询，服务端提交成功后唤醒读取方。发送端立即显示权威回执，历史按消息 ID 去重和排序。退出界面时取消监听并释放列表实例。目录由玩家手动更新。设密房间从目录打开独立的 `ArenaPasswordEntry` 预制体。密码保留四位数字，在弹窗确认时提交到服务器，接口只返回是否设密。无效密码、房间操作被拒绝和创建参数错误显示共用的底栏提示并播放禁止音。会话由服务端发放，客户端在同一进程内持有令牌。网络走与 Foundation 一致的 HTTPS 或本机回环 HTTP 地址。

`arena/directory`、`arena/create-room`、`arena/room` 和 `arena/zh-hans` 加入 Foundation 的 `HomeArena` 收集组。原版素材与截图对照见 `Res/Textures/source-manifest.json` 和[操作与验收](../../../../docs/development/arena-lobby.md)。

依据 2026-11-14 国服录屏优化。默认按人数降序，重复点击排序项切换方向，选择时保留筛选浮层。搜索需用户主动聚焦输入，提交后可继续修改，取消时解除过滤。创建页从疯狂征召开始展示。 点击弹窗外空白使用普通点击声，关闭提示将灰色叉号与文案组合居中。密码说明、分隔和输入框随设置密码选项统一灰显。允许聊天选中为绿，不允许选中为红。取消和确认复用 Common 按钮样式。房间聊天按头像、发送者、时间、正文排版，跟随底部时自动续滚，阅读旧消息时保持锚点。

模拟战工具条使用目录原版九宫格、分隔线和右栏选中贴图。锁房入场使用独立 ArenaPasswordEntry 预制体，校验失败保留弹窗并触发 Common GameToast。房间标示锁定状态，自己的昵称追加 [me]。聊天相对时间紧跟昵称，房间顶部使用原版黑色渐变，规则文字和成员列表背后都使用原版黑色光晕贴图，从中心向四边渐隐。成员列表从左上开始，每列三人，从上到下填满后再向右增加列。访客会话当前只有名称和头像，没有公会与大区信息。

`WindowCoordinator` 管理目录、房间以及筛选、搜索、创建与密码弹窗。目录交互记录必要的客户端语义事件，创建、进出房和聊天走服务端事务留痕。参见[操作留痕](../../../../docs/development/operation-audit.md)与[录像对照交付](../../../../docs/delivery/2026-11-14-arena-recording.md)。

房间聊天的表情从输入栏打开三列表情浮层，可滚动。底板取自原版 wnd/chat_emoji_tip.csb 对应贴图，使用薄棕边和不透明黑色内底。房间内使用独立的无压缩头像及头像框 Sprite，沿用 Common 头像预制体。服务端与资源导入验证使用同一组 67 个 `emoticon_chat` 资源 ID。客户端显示原版静态聊天图，文本和表情共用消息游标及禁聊规则。源素材及界面对照见[本轮复核](../../../../docs/delivery/2026-11-14-arena-ui-fidelity.md)。
