# Arena

与主页共用的简体中文表 `Configs/arena-zh-hans.json` 中，`home.gear.*` 用于英雄装备槽、背包筛选、穿脱确认和库存冲突提示。[主页装备界面](../Home/README.md)

预禁头像的五个叠加粒子发射器沿用原素材的源透明度混合。落章初始仍可宽幅闪白，之后白芯收缩，红色斜杠显现。主列表和最近选择均按最终画面中头像及邻位的覆盖率回归。[录像逐帧对照](../../../../docs/delivery/2026-11-21-preban-flash-r24.md)

预禁英雄的选择效果读取原包 `ui_pre_banned.cfx`，主列表、最近选择使用同一落章和三层粒子。底部头像显示已选阵容。全屏揭示期间两半立绘向相反方向连续移动，每组间隔 28 个录像帧，中央印章贯穿两组。战斗场景预载从揭示结束后开始。卡片列表共用底板投影，选人槽的横头像按原图高度对齐，可容纳薇薇安较宽的透明留白。[录像与验收](../../../../docs/delivery/2026-11-21-battle-and-summon-r23.md)

模拟战选人期间，己方行动点亮左侧蓝弧，对方行动点亮右侧红弧，另一侧露出暗金属框。换手时切边，同方连续选人或切换预览会接着当前亮暗周期播放。卡槽确认闪光有独立的生命周期。右侧目录与英雄详情共用卡片排列及吸附行为。[原版画面及复现](../../../../docs/development/arena-draft.md#角色滑条与引导光复核)

战场预载导致单帧耗时较长时，预禁揭示每帧最多推进 0.10 秒，确保逐组显示立绘、灰化和收起。服务端的选人时间仍按权威截止时间计算。结算后由登录导航选择大厅或仍有效的房间，再恢复 Canvas，房间恢复时跳过已经退出的该次对局。

正式启动完成登录和选服后，竞技场沿用该区服发放的会话和稳定玩家 ID。测试期使用服务端发放的访客会话，是否开放由服务端配置控制。 [游戏入口和区服会话](../../../../docs/development/game-entry.md)

模拟战目录、创建房间弹窗和房间页由独立 View/Binder 管理。目录用 ScrollRect 支持鼠标滚轮与触屏拖动。更新目录从服务端查询，可按公开状态、人数、最近创建和房名筛选。创建房名最多 28 字，支持四位数字密码、聊天开关、五个规则选项。进入「基本」房间后，房主可从顶部按钮设置预禁人数（0–3）和第三手禁用保护，在两个席位资料下方勾选一方先手。变更时房间聊天显示系统提示，两席准备复位。客席重新准备后房主可以开始，双方进入选禁。双方确认阵型后，竞技场通过当前 Foundation 资源包进入战斗。详细流程见 [联机选禁与入场](../../../../docs/development/arena-draft.md)。

区服正式账号的会话同时用于竞技场与英雄背包。测试直进时，由主页启动组合层复用当前竞技场的访客会话。选禁仍使用原有模拟战模板目录，持有英雄背包的实例不参与该规则。

房间打开后向 `GET /api/arena/rooms/{id}/events` 建立一条带区服会话的 NDJSON 连接。`sync` 在首次连接和重连时对齐成员、基本规则的选禁状态与聊天。`room` 更新成员和选禁状态，`chat` 从已展示的历史游标继续读取。消息按 ID 排序去重，发送者立即显示发送回执，回执不会跳过其他玩家较早的消息。服务端每 15 秒检查会话与成员租约并发送心跳；客户端据此更新聊天的相对时间，健康连接每两分钟再做一次完整校准。离开页面会取消订阅及在途读取。

断线后按 1、2、4、8、15 秒退避重连。事件接口不可用时，客户端约每 30 至 45 秒读取房间、草案和聊天，兼容既有房间租约。账号失去房间资格时返回目录。专项 PlayMode `ArenaRoomEventTests` 使用真实房间预制体验证空闲时请求数、拆包与连续通知、聊天补读和关窗后释放连接。

房间长连接使用 0.1.23 母包现有的 HTTP 传输。业务请求共用原有客户端，通知触发的房间、消息和草案补读顺序执行。该母包已裁掉修改 `ServicePoint.ConnectionLimit` 的接口。

事件订阅沿用普通竞技场请求的 `TryAddWithoutValidation`，将固定的 `Accept: application/x-ndjson` 写到请求头。R25 曾在房间已经创建、准备建立订阅时报告 `MissingMethodException`。0.1.23 Windows 母包保留了 `MediaTypeWithQualityHeaderValue` 类型和无参构造方法，裁掉了接收一个字符串的构造方法。发布验证须在已分发母包中实际创建、加入房间，并收到另一位玩家的聊天。

目录由玩家手动更新。设密房间从目录打开独立的 `ArenaPasswordEntry` 预制体。密码保留四位数字，在弹窗确认时提交到服务器，接口只返回是否设密。无效密码、房间操作被拒绝和创建参数错误显示共用的底栏提示并播放禁止音。会话由服务端发放，客户端在同一进程内持有令牌。网络使用与 Foundation 一致的 HTTPS 或本机回环 HTTP 地址。竞技场复用同一个托管 HTTP 客户端发送请求，回环地址直连，请求取消随窗口和入口生命周期传播，退出入口时释放连接。

`arena/directory`、`arena/create-room`、`arena/room`、`arena/draft`、`arena/draft-art` 和 `arena/zh-hans` 加入 Foundation 的 `HomeArena` 收集组。原版素材与截图对照见 `Res/Textures/source-manifest.json` 和[操作与验收](../../../../docs/development/arena-lobby.md)。

依据 2026-11-14 国服录屏优化。默认按人数降序，重复点击排序项切换方向，选择时保留筛选浮层。搜索需用户主动聚焦输入，提交后可继续修改，取消时解除过滤。创建页默认选中基本，并将规则横栏滚至基本卡。 点击弹窗外空白使用普通点击声，关闭提示将灰色叉号与文案组合居中。密码说明、分隔和输入框随设置密码选项统一灰显。允许聊天选中为绿，不允许选中为红。取消和确认复用 Common 按钮样式。房间聊天按头像、发送者、时间、正文排版，跟随底部时自动续滚，阅读旧消息时保持锚点。

共享的 arena/zh-hans 同时提供主页更多、英雄详情和背包工具栏文案。

模拟战工具条使用目录原版九宫格、分隔线和右栏选中贴图。锁房入场使用独立 ArenaPasswordEntry 预制体，校验失败保留弹窗并触发 Common GameToast。房间标示锁定状态，自己的昵称追加 [me]。聊天相对时间紧跟昵称，房间顶部使用原版黑色渐变，规则文字和成员列表背后都使用原版黑色光晕贴图，从中心向四边渐隐。成员列表从左上开始，每列三人，从上到下填满后再向右增加列。访客会话当前只有名称和头像，没有公会与大区信息。

`WindowCoordinator` 管理目录、房间以及筛选、搜索、创建与密码弹窗。目录交互记录必要的客户端语义事件，创建、进出房和聊天走服务端事务留痕。参见[操作留痕](../../../../docs/development/operation-audit.md)与[录像对照交付](../../../../docs/delivery/2026-11-14-arena-recording.md)。

房间聊天的表情从输入栏打开三列表情浮层，可滚动。底板取自原版 wnd/chat_emoji_tip.csb 对应贴图，使用薄棕边和不透明黑色内底。房间内使用独立的无压缩头像及头像框 Sprite，沿用 Common 头像预制体。服务端与资源导入验证使用同一组 67 个 `emoticon_chat` 资源 ID。客户端显示原版静态聊天图，文本和表情共用消息游标及禁聊规则。源素材及界面对照见[本轮复核](../../../../docs/delivery/2026-11-14-arena-ui-fidelity.md)。

## 选禁界面来源与验收

选人、终禁和阵型采用原版玩家布局的 1280×720 设计坐标。原版 CSB 记录卡槽镜像、头像边缘锚点、轮廓、圈位和换位按钮坐标。待选框按各槽原版 Spine 附件的尺寸居中，使亮边沿整张底板轮廓呼吸。我方蓝色、对方红色。运行时生成的骨骼模型显示比例须用原作录像对照。当前试用每个源像素约 0.435 个设计像素，并基于初始网格为超宽或超高模型一次性缩小，保留足底锚点。宽屏按统一设计画布等比显示，可能留有边缘空白。

在 D 盘主工程运行 `& ./.tools/character-assets/Scripts/python.exe -X utf8 -B Tools/Arena/InspectDraftLayout.py`，在 `.artifacts/arena-draft/revision` 生成原版布局结构 JSON 和素材图册。等级、数字和星级的独立复核入口是 `Tools/Arena/ImportArenaArt.py --team-badges-only --check`。各组源坐标、对应素材和待核对项见[选禁与阵型原始布局审计](../../../../docs/delivery/2026-11-15-draft-source-audit.md)。

本轮先交付房间设置、预禁、选角闪烁、禁用防护与入场的 Unity 实机截图，用户确认后才构建或发客户端包。

BP 待选框沿槽位轮廓呼吸。服务器确认新增选人后，按本机视角播放原包同槽的 `blue_set` 或 `red_set` 骨骼与粒子。中央立绘保留待机、短暂上跳并用轮廓白闪渐退。录像 4:24 附近的确认卡槽先短白闪，再还原头像细节并退出亮边和星点；原包分层颜色和 Unity 离屏合成的调校记录见[选禁流程](../../../../docs/development/arena-draft.md)。预禁底栏使用原 CSB 尺寸的头像和金框，红色印章越过金框外沿。终禁起始隐藏立绘，选择目标后用去色立绘与暗卡提示，提交成功播放原包中央 BANNED 和红橙粒子。双方终禁结果公开后，在靠中轴的印章位同步播放缩小的原包终禁爆光与火星，随后保留静态红章。阵型模型的显示面绕原脚点放大 50%，超宽或超高模型保留按原待机网格的限幅。预禁已提交后暗显「选择」，对手选人和本方终禁、阵型已提交时暗显「等待中」。保护槽依源文件镜像并显示本地化说明。配套服务端必须注册预选接口，对手才能同时看到预选卡槽的闪烁和中央立绘。出现只见红框时，按上面的选禁流程文档核对当前服务进程；Windows 成品验收会检查双向预选。选人阶段预载战斗场景和已锁定的角色模型，阵型最终确认后按权威快照接管。两侧弧形进度按当前选禁截止时间填充，空槽、蒙层、轨道在同一设计坐标对齐。双方预禁头像分组，图标和标题整体居中。阵型常规播放 `idle`（缺失时才回退 `b_idle`）。顶部不放返回箭头。右栏小卡按原包斜切底板、肖像蒙版和觉醒星贴图拼装。初始第一张位于第三个视觉槽；滑动时焦点卡保持最高绘制层并向左跨过边栏分隔线，所有卡片贴齐右边界并沿竖向相叠。列表保留上下裁切，只有卡片本身能在边栏外接收点击，空白拖动区仍在边栏内。目录只显示战斗配置中的速度，不显示尚未接入的账号装备加成、锁定状态等资料。筛选底板按原包九宫格切片，详见[筛选说明](../../../../docs/delivery/2026-11-15-draft-roster-filter.md)。

共享中文文案表提供召唤普通 UP 标签和愿望单的职业筛选、推荐名单文案。这些界面由 Summon 模块生成。

房间目录左上使用公共 HeaderBackButton，返回先处理当前浮层，再回主页。

选禁目录 `ArenaDraftArt` 按战斗表生成 40 名英雄的头像、卡图、动态立绘与战斗模型。新增状态也要同步更新选禁 Prefab 内的筛选候选，本批在弱化中增加炸弹、吸血之手，强化中增加反射。[角色目录验收](../../../../docs/delivery/2026-11-20-roster31-40-assets.md#主页与竞技场目录)

BP 角色目录已覆盖 50 人。随机状态候选分别进入实际增益或减益，依目标、暴击或施加状态获得的行动值可用提高行动条筛选。六种新增状态能从相应组进入筛选。[第 41–50 名角色验收](../../../../docs/delivery/2026-11-20-roster41-50-assets.md)

选禁目录现在覆盖 60 名普通英雄。基础模型由正式角色目录选择，支持同一英雄拥有多个模型文件。塔玛林尔、卡威利、菲奥雷托分别可按歌姬、魔力力场、识破的实际正面效果筛选；修尼尔可解除剧毒，选禁筛选以实际赋予状态和实际技能结果为准。 [第 51–60 名角色资源与验收](../../../../docs/delivery/2026-11-20-roster51-60-assets.md)

## 第 61–70 名普通角色

第 61–70 位增加 10 张普通选人侧脸，团队、英雄目录与选人资源覆盖 70 人。迪埃妮的穿透抗性提升归入强化，杰诺的冻伤和破裂归入弱化。护盾按璐璐卡的攻击力结算时也能筛出，卡瓦朱触发被动的推进可按速攻值提升筛出。普通召唤结果、英雄详情所用的本批简中获得语、人物简介、故事和日语演员共 40 项。 [本批来源与验收](../../../../docs/delivery/2026-11-20-roster61-70-assets.md)
