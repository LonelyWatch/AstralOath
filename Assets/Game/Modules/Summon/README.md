11/28仅重新保存嵌套MailEntry的顶栏，统一邮件角标源位置/九宫格/原数字字体；卡池、召唤事务与演出未改。[邮件UI复核](../../../../docs/delivery/2026-11-28-mail-ui-followup.md)分别记录本轮验收与未覆盖场景。

内容43同步保存补齐TMP初始化特殊字形的嵌套角标，原字库/图集GUID保持；描边由Foundation SVC显式保留，不改召唤业务代码。

邮件奖励的余额校准可调用当前 `SummonWindowBinder.RefreshExternalAsync`：重新读取当前登录账号的召唤状态，在原 Binder 内更新余额、持有和卡池读数，保留当前卡池、未保存愿望单、类别及筛选，不重新执行页面 `OpenAsync`。读取等待本页已开始的操作结束，调用方与页面取消任一触发均停止；旧页面读回不得更新后来重开的页面。该入口当前已完成源码接入，专门的原生邮件→召唤返回场景仍须在最终联合验收记录，不以 Home 的三个受控库存用例代替。

召唤确认弹窗恢复 Common 的源横幅渐变与细边，移除 `SoftModalSurface` 实色内衬。细边覆盖率按 Unity Linear 校正，源图自带线条不重复绘制；弹窗继续保留底层实时技能预览。[来源与图形复核](../../../../docs/development/ui-material-reference.md)

循环声、召唤获得语音及打开演出的取消通过 `UiAudioPlayback` 进行 0.20 秒渐出，页面隐藏立即停止图形和输入。独立音源继续完成尾音，恢复循环时沿用保存的采样位置。两名召唤小人的头部有效图块约 168×170、164×161，在 4K 下明显放大，R35 对应源图的解码像素一致。[采样与声音验证](../../../../docs/delivery/2026-11-23-equipment-battle-review.md)

召唤页底部信息、历史及设置圆钮按 720 高参考画面的 76×76 底板排版，可见外沿约 68 像素。半透明底图在项目的线性色彩空间下需要校正。单次与十次召唤保留原按下底图，价格、资源图标和按钮文字和底图同时产生按压反馈。确认框截获点击，底层召唤展示继续播放。

召唤结果和心愿单的设计尺寸保存在预制中。主页复用预热窗口时只更新显示比例。R22 中同一窗口二次绑定会把容器算成 0×0，双开截图中第二个窗口只剩头像。现已用同一实例连续验证单抽、十连和四种窗口比例。[复现与截图](../../../../docs/delivery/2026-11-21-battle-and-summon-r23.md)

召唤确认弹窗允许点击材料不足的报价。余额不足时显示“材料不足”，保留弹窗和身后的结果页，玩家可以取消。多开导致服务端判定书签不足时同样提示并重新读取余额。十连结果的「再召唤一次」沿用上次的抽数、币种和价格，整个按钮都可点击。

获得演出的动态立绘和小人按实际投影像素选择渲染目标。结果横卡按每张头像的原始宽高等比放大 1.1 倍、右下对齐并裁切。通用规则同时适用于席可和宽头像。资产核对与实测见[本轮界面验收记录](../../../../docs/delivery/2026-11-20-home-and-arena-ui.md)。

主页「更多 → 召唤」打开 SummonWindow。SummonWindow 按 BindingMap 读取预制体节点，SummonWindowBinder 管理卡池、愿望单、弹窗、回执和演出。需要重新生成预制体时，运行 Unity 菜单「Tools → 游戏主页 → 生成召唤和神器」。

服务端 /api/summon 返回当前账号及区服的池版本、实际概率、货币和免费次数。提交时使用回执 ID 幂等重试。在收到已结算回执后才播放演出，用户随时可以跳过。再次打开时可查看上次结果，溢出的奖励在保管箱内领取。开发账号首次进入本区服发送测试票券。

配表与服务端实现位于 Server/Host/Summon。原版界面、骨骼、音频的路径和哈希见 Res/Textures 与 Res/Presentation 的 source-manifest.json，核对方法见原版召唤演出交付记录。

首次进入时优先显示已开放的伊赛丽亚概率 UP。誓约七人立绘、愿望单和十连结果以固定设计尺寸成组缩放。愿望单左侧同时显示七名英雄与七件神器，右侧每行五个候选。切换类别后仍可从左侧移除任一类别的选择。两个类别各选满七个时可以保存。

誓约召唤七张立绘的白色斜体名字共用 `SummonWishNameOutline.mat`，字面扩张为 `0.10`，暗色描边宽度为 `0.09`。通过「更多 → 召唤 → 誓约召唤」核对七个名字，以 1478×720、960×720、1680×720 的截图检查笔画间隙和亮背景上的可读性。回归记录和截图保存在 `.artifacts/summon-wish-font/`。

单抽、十连、免费气泡、愿望单与再次召唤各使用对应的普通态和按下态。价格底板使用源九宫格和线性色彩空间的透明度换算。中文字体与原布局指定的 daum.ttf 哈希一致，按钮、价格和标题分别使用对应字号与描边。愿望单可按持有情况、职业筛选，推荐列表取当前区服默认名单；有未保存的改动时显示确认按钮。

结果与揭晓分别独占整页；再次召唤的确认浮在结果之上。信息按钮默认显示注意事项，机率页按区服实际池分栏列出英雄和神器。齿轮打开本客户端的召唤设置，可切换卡池技能演示、查看最近回执。UP 召唤确认使用圆形战斗头像，首次获得英雄显示原版简中获得台词、日文语音及对应声优；重复获得可重听。顶部依次展示金光传承石、银河书签、神秘奖牌、誓约书签、天空石，保底与活动时间分别显示。

抽卡成功时按回执更新当前登录的英雄和神器。满仓奖励留在保管箱，领取成功后进入库存。重复回执按请求和实例去重，查看历史回执只回放演出。服务端拒绝抽卡保留已有缓存。免费召唤重置与卡池日期按服务端时间判断。

伊赛丽亚 UP 页由 `SummonSkillLoop` 控制海报、声音和实时战斗画面间的过渡。技能使用 `c_iseria_skill_03`、当前战斗镜头修订和原手绘切入。开预览时创建角色、目标和相机，切池及关窗时释放。召唤确认框继续播放后方的技能，进入结果页暂停。更新演出参数会直接反映到召唤页，若增减技能依赖，用「Tools → 召唤 → 更新伊赛丽亚技能预览资源」重建引用。国服录屏中各池的战场和受击角色不同，当前伊赛丽亚沿用项目原有森林和单体冰史莱姆。[原版录像与项目 4K 实拍](../../../../docs/delivery/2026-11-22-client-image-quality.md)
