# 第 46–50 名角色的战斗权威

取数基线为 pack-15-r4262 的 `db/skill_player.db`、`db/cs_player.db` 和简中技能、状态帮助文本。普通、第三觉醒、灵魂燃烧及触发子技能分别读取。以下编号均为固定包内的技能或状态 ID。

- **克萝爱 c1049**。S1 对魔法钉目标增加 30% 伤害。S2 先提升自己的攻击力，再造成伤害、施加三回合魔法钉并自拉条 50%。第三觉醒无视效果抗性。S3 只对已有魔法钉的目标无视眩晕的效果抗性。原状态 222 给攻击者挂接 1086，`HPDOWN_CASTER_ATT=0.8`。简中帮助也明确写“根据攻击者的攻击力”，额外伤害由实际攻击者触发。
- **泰妮布里雅 c1050**。S1 攻击所选目标和另一名敌人，基础睡眠概率 60%。第三觉醒按每次成功施加睡眠自拉条 25%。S2 驱散一个强化，退条 20%，并施加两回合降速、无法强化。S3 全体破甲，70% 概率睡眠，再给自己提攻。固定包帮助明确睡眠使受术者无法行动、暴击抗性和回避降低 100%，并在受到攻击伤害时解除。后排援护和免疫无法行动类弱化效果的规则识别睡眠。
- **巴萨尔 c1053**。S1 以 50% 基础概率转移自身一个弱化后，才从攻击降低、防御降低、禁疗和沉默中抽取一个两回合弱化。源第二行条件为 `ADD_EFF_ACTION`。S2 的命中降低、攻击降低各有 60% 基础概率。S3 源 `BUFF_REMOVE=20`，按目标作一次驱散抵抗检定，第三觉醒再施加两回合无法强化，最后退条 30%。魂燃无视这些效果的抵抗。
- **铃儿 c1054**。S1 和 S2 分别增加自身最大生命值 5%、7% 的伤害基数。S2 的追加掷环独立 50% 判定，子技能 `sk_c1054_4` 使用 S1 强化并获得一魂。S3 先按各目标最大生命 20% 治疗，再从七种原强化中抽取一种，第三觉醒抽取两种不同强化。魂燃将三回合延长到四回合。七种选项为攻击力大幅提升、暴击率提升、暴击伤害提升、防御力提升、持续恢复、回避提升、免疫。
- **济纽亚 c1055**。S1 在攻击前为自己提攻，魂燃改为攻击力大幅提升。狂气状态仅在自身回合追加 S3，每回合最多一次。S2 的隐藏状态 `pa_c1055_9` 给出一次致命保护和一回合不死。其次数贯穿整场战斗，独立于 A 计划的五回合冷却，强化后四回合。自身受击后不足或等于半血时，A 计划净化自己、获得两回合狂气并自拉条 50%。S3 `def_pen=1`，造成击杀时灭亡。第三觉醒按主目标实际损血吸血 25%。`pa_c1055_8` 要求主攻击命中，再用 `pa_c1055_3_cs` 的 `HPDOWN_CASTER_ATT=0.6` 向其余敌人追加伤害，主目标存活也能触发。A 计划沿用 `sk_c1055_3` 动作并播放 `c_jenua_skill_03`。主动及追加 S3 均用 `sk_c1055_2` 动作，播放 `c_jenua_skill_02`。

铃儿的原表以一个全队接收数组描述随机增益，各受术者获得指定数量且自身没有重复项。不同受术者之间的随机序列，以及济纽亚追加技能在原目标阵亡时 `target=135` 的精确改选优先级，尚无同版逐帧或原引擎枚举证明。后者沿用既有追加技能的存活目标选择。

## 实表复验

从项目根目录运行 `dotnet test Server/Tests/AstralOath.Server.Tests.csproj --no-restore --filter FullyQualifiedName~BattleRoster41LastTests`。测试使用服务器嵌入的正式战斗目录，通过 `BattleMatch.Submit` 检查行动、伤害、状态、冷却、魂和表现图 ID。

1. 首轮测试记录了济纽亚主攻闪避后错误的全体追加伤害，以及自身回合被其他技能调用的 S1 无法继续追加 S3 两项偏差。补上原表命中条件、按实际回合和每回合触发次数处理后，这两项和其余五人用例共 24 项通过。
2. 丽迪卡魂燃 S2 对低血量的济纽亚成功施加拘禁时，旧实现仍会发动 A 计划、消耗冷却、净化拘禁。改为在被动触发前判断行动资格后，拘禁一直保留，A 计划不产生动作也不进入冷却。用普通攻击打到同一生命范围时，被动正常发动并进入五回合冷却。加入这两个对照后，后五人专项共 26 项全部通过。
3. 将五人专项与共享技能、濒死保护、吸血和被动反应测试合跑，144 项全部通过，零跳过。

## 泰妮布里雅的双轴镜像

实战采帧在第 47 名泰妮布里雅的 S2 和 S3 报告六个原语无法读取 `scale`。战场此前只接受两个大于零的轴值，实验室只允许单值，两处均在创建渲染对象前丢弃整层。

- 原始 `effect/tenebria_skill_02.cfx` 的第 8、9 号原语（从 0 计）在 2333 ms 同时播放同一个 `tenebria_skill_02_pati4`。两者都位于 Y=142，X 分别为 +600、−600。右侧使用默认缩放，左侧显式写 `-1.0,1.0`。同一文件用 `0.8~1.2` 表示随机缩放。
- 原始 `effect/tenebria_skill_03.cfx` 的第 6–9 号原语都播放同一个 `tenebria_skill_03_up_doom_L`。深度依次为 3、3.1、3.2、3.3。四份分别采用默认值、`-1,1`、`-1,-1`、`1,-1`，补齐四个象限。波纹和月亮则各有上下两份。
- 独立同源样本中，`iseria_skill_02.cfx` 在 1700 ms 把同一树屑粒子按 X=±200 成对放置，`ruell_skill_03_final.cfx` 在 1200 ms 使用 X=±350，两者各有一份 `-1,1`。`serilla_skill_03_2.cfx` 在 900 ms 按 Y=±1000 放置成对粒子，其中一份使用 `1,-1`。这三组分别确认逗号前后对应 X、Y。

读取显式双数值时保留各轴符号，在原语原点上缩放，位置与延迟继续独立读取。战场分别将镜像作用于 Spine 和粒子的父节点，实验室的两种原语同样保留双轴。当前只开放有限、非零的固定轴值，混合区间或损坏字段继续产生诊断。

EditMode 首测的三个用例均失败，日志和 XML 位于 `.artifacts/roster-41-50/cfx-axis-RED.*`。战场实测用原图集和 Spine 2.1.27 骨架在局部 2.55 秒比较四份可见顶点的世界坐标。另将每层单独渲染到 256×256 图像，四张均产生可见像素，亮区重心与基准层按源轴镜像的误差均小于 2 像素。实验室在 S2 成对粒子发射后的 0.13 秒比较实际网格的世界坐标，所有顶点 X 成对取反、Y 相同。连同旧 CFX、粒子色阶及镜头范围测试共 41 项通过，记录在 `.artifacts/roster-41-50/cfx-axis-PIXELS.xml`。


## 肯恩 S3 的文字、闪电与镜头

固定包 `c_ken_skill_03` 在 3.732 秒启动 #17。它显式绑定施法者，`ken_skill_03_bg.cfx` 播放前后两层岩壁。并行的 #18 没有 `location`，给出 X=−190、scale=0.55、`disableAutoFlipX=true`。`ken_skill_03_tx.cfx` 只有一个 Spine 原语 `ken_nbg_tx`，槽包括渐变底、十个闪电槽和两份书法字。项目源时 4.5 秒的灰白矩形和电光边都对应这个原语。当时距 #18 起点为 768 毫秒，#26 的反色在第 825 毫秒才开始。

普通形态日服录像发布于 2025-10-03，媒体时间 32:02.60 可见紫电，32:03.12 可见黑字。该段可见操作按钮，倍速数值未读到。将项目 1920×1080 定步截图归一至原片的 854×480 后，原片右侧字形的深色区域高约 414 像素，项目修正前高约 223 像素。另在 32:04.35 取岩壁，对齐项目源时 6.5 秒的三个红色裂纹局部，最佳尺度约为 1.09、1.095 和 1.115。字层相对岩壁还有约 1.67 倍的尺寸差。前排阵型缩放与 #19 的相机倍率都恰为 0.60，单独量字不能区分两种原因。[原片](https://www.youtube.com/watch?v=8PPBeDcevjg&t=1922s)

原图随后从 0.60 放大至 0.65 并返回，每段 50 毫秒。按 1/30 秒取样，32:03.487、32:03.587、32:03.653 的肯恩血条绿段左端依次为 (288,310)、(278,302)、(288,310)。在同期比较两侧独立闪电轮廓，脉冲期间左侧轮廓中心的水平位移小于 1 像素，右侧约 0–1 像素。如随世界镜头缩放，则左右相距约 650 像素的纹理间距将增加约 54 像素。源骨架在这个区间没有对应的闪电缩放或位移关键帧。参考切片 `references/ken-pulse-00.png` 至 `ken-pulse-24.png` 和相机记录位于 `.artifacts/roster-41-50/`。可用较远两个轮廓作测点，同时跟踪一个确实随镜头移动的战场标记。

实战按 STG 的禁自动翻转字段保持特效内部的原始朝向，敌我双方都能正向读字。世界位置偏移继续按出手侧布置。经上述独立脉冲验证的 #18 按战场基准画幅投影，视口中的点位与尺寸保持稳定。显式地点与其余待考的无地点特效沿用各自路径。#18 的原生绝对基点仍待有坐标取证或不同站位录像，当前取特效开始时主目标及作者偏移的投影。检查后续同类资源时，应分别验证接收点、基准画幅、队伍翻面和镜头脉冲。

EditMode 从真实 #18 进入战场播放，两方与移除禁翻字段的三例中，修正前仅敌方的原字形发生镜像。修正后全部通过。真实 #19、#20、#22、#23 的脉冲回归同时观测一个可见网格顶点和投影宽度。修正前，文字宽度错误增至 1.08333 倍。修正后顶点和宽度均固定，施法者显式绑定的对照层仍正确放大。记录位于 `.artifacts/roster-41-50/ken-layout-red.xml`、`ken-pulse-red.xml` 和 `ken-pulse-green.xml`，最后一轮 35/35 通过。

修正后重拍正常战场。归一至 854×480 看源时 4.5 秒，灰白底覆盖视口两侧，原来清晰可见的大矩形外框消失。5.0 秒右侧字形的深色区域从 223 像素增至约 373 像素，参考为约 414 像素。项目闪电下缘约在 y=409 与 HUD 上沿相接，原片继续向下。两张字形的顶部和底部仍有绝对位置差。复查应保留源时 4.5 和 5.0 秒的同屏 HUD、施法者脚点，以及不同站位下的同款录像，用于区分绝对基点与整体战斗构图。采帧见 `.artifacts/roster-41-50/battle-frames/source-playback/c1047-s3-source-4.5.png` 和 `c1047-s3-source-5.0.png`。
