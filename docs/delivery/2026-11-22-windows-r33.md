# Windows 训练版 R33 增量更新

R33 使用 R32 的 0.1.25 Win64 母包，业务源码来自 `2e7dd1f1`。本机试玩继续双击 `.artifacts/windows-r32/Play-R32.exe`。这个启动器负责连接本机训练服及资源源，实际运行的游戏程序是 `.artifacts/windows-r32/client-r32/AstralOath.exe`。两者都沿用原文件。

## 下载与缓存

R31 到 R32 改过产品名和母包基线。两版有 91 项内容相同，但 R32 从新的产品目录和基线目录寻找缓存，首次实测下载了 2,238,374,796 字节。[R32 原生记录](2026-11-22-windows-r32.md)

R33 沿用 R32 的产品目录和基线 `e009595d3a8a4186a1ffaad76323e806`。使用原母包内置公钥验证 R33 清单和签名。98 项中复用 89 项，更新 6 个资源包和 3 个清单相关文件。9 个文件合计 54,990,555 字节（52.44 MiB），另有签名和清单请求。

在隔离的 R32 缓存中，用项目实际的 ContentUpdater 分进程验证拒绝、同意安装和冷启动。拒绝时保留 R32，同意后安装 R33 并要求重启，再开时业务资源下载为 0 字节。本机原生缓存也使用该更新器，通过 5303 下载并校验了同样的 9 项。物理缓存现位于 D 盘，R32 保留为上一版本。[存储迁移核验](../development/local-storage.md)

## 原生桌面与开发服

以普通交互用户从 Windows 桌面启动原 R32 游戏程序，冷启动激活 R33。再次打开时业务下载为 0 字节，训练账号进入背包读到 7 件装备。配戴头盔后生命值从 263 升至 343，卸下恢复至 263，进程正常退出。

另从日常入口 `Play-R32.exe` 启动，核对了子进程的可执行文件路径，实机截图显示标题和登录按钮。训练启动脚本的 `--verify` 已指向 R33，并用另一个测试账号通过了原生装备穿脱。`.artifacts/windows-r33/desktop-independent-launcher.png` 是启动器拉起游戏的桌面截帧，第二次装备回执在 `.artifacts/equipment-player/34fe125c8b7843d9b40b9553ffdb6fcf/verified.json`。

开发服仍在 `127.0.0.4:7728`，签名源仍在 `127.0.0.1:5303`。切换时确认没有活动客户端和房间，保留原 MySQL 进程。新服就绪检查返回 200，未登录请求访问 GM 返回 401。登录后可在开发版的 GM 悬浮入口打开资源、库存和诊断面板。[客户端功能与验收](../../Assets/Game/Modules/FoundationDemo/README.md) · [服务端接口](../../Server/README.md)

桌面验收与 Codex 应用环境分开记录。Codex 下逻辑 LocalLow 路径曾在替换启动临时文件时失败。同机用相同脚本独立启动 Windows 桌面进程，原路径与 D 盘目标的文件替换均成功，再用实际游戏验证了上述冷启动与装备操作。首次安装的数据量来自共享更新器，游戏内实测覆盖已安装后的激活与重开。

签名与差量回执是 `.artifacts/windows-r33/build/receipt.json`。同目录树中的 `offline-updater/runs/bb7d4c44d41644d4bd1bf915152476c6/install.json` 记录原生缓存的逐文件传输，`desktop-independent-startup.result`、`desktop-cached-reopen.json` 和 `server/cutover.json` 分别记录原程序启动、重开传输及训练服切换。原生装备数据在 `.artifacts/equipment-player/91a3d3f55d1f42e6817fd46455ea2503/verified.json`。
