# Windows 装备与神器试玩 R31

源码提交为 `f3f51dd9`。本次整钮按压涉及稳定启动层依赖的 Common 程序集，Windows 试玩使用 0.1.24 母包和 R31 签名内容。原有装备训练服地址为 `127.0.0.2:7728`，R31 使用独立的本机内容源 `127.0.0.1:5302`。

新训练游客初始有七件普通装备、60 枚誓约书签，神器库存为空。可在「更多 → 召唤 → 誓约召唤」抽卡后到背包查看获得的神器。测试中的多件神器来自单独创建的测试账号。

## 神器操作

- 从英雄页点已穿神器，打开带立绘、技能、背景和佩戴信息的详情。点「更换」进入独立配戴页，右侧单列选候选，确认配戴后回到该英雄。空槽直接进入配戴页。
- 从背包点神器，双列横卡与右侧详情同时可见。英雄配戴页与背包共用卡面。两个容量入口均显示账号实际使用量与 400 格上限，点击显示上限提示。关闭提示恢复原页面。
- 从物品进入强化后，在右侧选材料、点击已选材料撤回，核对经验、费用和属性预览，再确认强化。材料库存和金币由训练服结算。
- 普通装备在英雄身上、背包英雄行和装备管理中使用同一套品质底、图案、等级与强化角标。背包英雄行可以直接看已穿物品或进入该英雄的管理页。

## 图形验收

Unity 编辑模式最终回归 `final-edit.xml` 通过 22 项。D3D11 下的 `final-cards.xml` 通过整钮按压、英雄神器配戴与解除、背包神器详情与强化三项。窄窗实测中，最右侧职业筛选与容量按钮可以分别点击，配戴页容量提示的确认钮能通过实际指针命中。召唤独立回归覆盖确认弹窗期间的动画，以及确认后的十连结果。不同测试批次有重合，不累加为独立用例数。

## Windows 包与更新源

本机启动入口是 `.artifacts/equipment-r31/Play-Equipment-QA.cmd`。原生构建使用提交中的 23,497 项输入，母包基线为 `0385ffccb5214a15a43935d9ad762909`。验签使用从成品客户端读取的公钥，清单 SHA-256 为 `8a47a12fb3f361991989026b2c5a0a1fe9247a4a1a2423fdba13ce4c60c25df6`。98 个签名业务文件的总大小为 2,238,361,215 字节，9 个文件相较 R30 有变化。实际下载量随缓存而定。

从空业务缓存首次启动实测下载 2,238,361,215 字节，再次启动新增下载为 0 字节。两次都在 D3D11 原生客户端读到七件训练装备，拉斯的生命值在配戴前、配戴后、解除后分别为 263、343、263，背包和单槽的头盔描述相同。正常启动入口也通过了两进程同时运行检查。回执在启动脚本同目录的 `first-activation.json`、`cached-reopen.json`、`transfer-receipt.json` 和 `multi-launch.json`。

成品客户端另用独立训练游客完成誓约十连，显示十张结果卡。在五种窗口大小之间切换时，五张替换的渲染纹理均采到有效画面。开启再召唤确认框、关闭确认、返回召唤页成功，进程退出码为 0。详情见启动脚本同目录的 `summon/8e2553bb4e064b6c8cb82faae93251ef/verified.json`。
