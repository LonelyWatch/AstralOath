# Windows 本机试玩 0.1.23 / R26

R26 修复模拟战房主创建房间后，Windows 客户端弹出 `MissingMethodException` 的问题。房间已经在服务端创建，错误发生在客户端订阅房间事件时。R25 通过强类型 `Accept` 请求头调用了 0.1.23 原生母包裁剪掉的 `MediaTypeWithQualityHeaderValue(string)`。R26 用母包支持的方法发送相同的 `application/x-ndjson` 请求头，继续接收房间和聊天推送。

## 构建与签名

- 根据提交 `7eccc447227e727ad9f67075d4fd96e416a3f408` 核对 23,284 个 Git/LFS 输入，复用 Windows x64 母包 `25cda4dbafde4770b98611b1323689a1`。签名协议为 1，清单结构为 3。
- 使用从交付母包提取的公钥，分别验证构建输出和交付副本。清单有 98 个文件，共 2,235,517,410 字节，SHA-256 为 `8c93dbd1bd9f6ba851045b56f055aca7195665c0f23e7c8cfc7761de28aaadd9`。R25 缓存可沿用其中 92 个文件，其余 6 个文件共 3,187,256 字节（3.04 MiB）。构建回执位于 `.artifacts/r26-release/build/receipt.json`。
- 首轮隔离双端测试还发现，测试入口等待整场演练完成才返回，延迟了启动确认，导致第二个进程等待共享缓存锁。候选 `ad4d7a37` 留存在 `.artifacts/ui-r26/qa/attempt-ad4d7a37/`。交付候选将测试放到启动确认之后，并从已重新激活的 R25 缓存开始复验。

## 本机启动

服务就绪后，双击 `.artifacts/ui-r26/delivery/AstralOath-Play.exe` 可再开一个窗口。已运行的窗口继续使用该次进程加载的业务代码。旧客户端收到更新提示后，完成下载、退出并重新打开即可启用 R26。游戏服务使用 `127.0.0.1:7728`，签名内容源使用 `127.0.0.1:5295`。
