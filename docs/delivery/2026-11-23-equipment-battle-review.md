# 装备界面及战斗反馈复核

## 复核范围与依据

用户指出上一轮的装备 UI 与参考效果存在明显差异。本轮重新检查管理装备、已穿普通装备、已穿神器和英雄页，逐状态参考见 [装备实录](../development/equipment-ui-reference.md)。录像文件日期来自文件名，公开日期、客户端版本和游戏倍速未知。当前修改基于 `4b18dc10`，沿用 AstralOath 深蓝界面样式。

改动前的运行截图在 `.artifacts/equipment-manage-followup/final/`。管理页存在小字号、细小候选卡、未选择时预览属性隐藏、筛选缺项、未选时按钮看起来仍可用和确认窗内容分布松散的问题。已穿详情过宽，背景角色干扰正文。上一轮 Unity 图形回归为 8 项中 6 项通过、2 项失败，失败分别涉及筛选真实射线点击和眩晕演出时钟。该结果不能作为整体完成依据。弹层刚启用的同一帧，Graphic 深度仍为 -1，下一帧才注册到射线列表，回归在绘制后一帧执行真实点击。

复拍额外发现管理页空槽不可见。编辑器在零宽父节点上启用宽高比约束，把锚点位置写为 NaN。预制生成时保持该组件禁用，运行时页面具有实际 Canvas 宽度后再启用。底板按九宫格绘制并单独控制边缘缩放，位置有限性加入回归。这个故障说明组件存在或绑定成功无法替代实际渲染检查。

管理页调整可读字号和候选卡尺寸，左右属性保持可比较，支持套装及主、副属性选择，空条件清除后恢复目录。点击六个装备位能切换当前部位。确认列账号实际的前后属性和差值，取消不修改库存，成功配戴后回到管理页。项目没有原片中的总战力公式，确认使用实际面板属性。普通装备强化和推荐配装仍依现有功能边界。复验须检查选前、候选、取消、确认和提交后五个状态，以及宽屏和窄屏。

## GM 装备规则

开发 GM 新增锻造页，操作作用于当前登录账号。六个部位的主属性、禁止的副属性、重复属性、品质解锁时间和累计掷次预算由服务端校验，客户端使用服务端返回的同一规则显示可选项。请求重试保持幂等，装备写入、版本变化和审计同事务完成。旧训练装备保持可读取和配戴。

品质与强化解锁参考维护者发布的 [属性生成表](https://github.com/meowyih/meowyih.github.io/blob/master/epic7-gear/README.md#number-of-substats-for-different-gears)。稀有第三、四条分别在 +9、+12 生成，到 +15 两条合计仅能追加一次。英雄第四条在 +12 生成，到 +15 最多两掷。普通品质 +3、+6、+9、+12 的解锁是项目自定规则。70/85 级支持 +0 至 +15，90 级仅支持 +15，主值和掷值按项目公开规则表校验。原作再锻造资格参考 [2020-04-16 官方更新](https://page.onstove.com/epicseven/global/view/5123027)，原作后续版本未纳入本轮规则。

服务端隔离 MySQL 回归 15/15 通过，记录 `.artifacts/equipment-manage-followup/server/all.trx`。修前原实现对新增的解锁预算用例有 4 项失败，记录 `milestone-red.trx`。GM 延迟锻造请求中锁定提交配方的回归见 `revision/gm-forge-freeze-green.xml`，原失败见同目录 `gm-forge-freeze-red.xml`。该用例主动尝试将提交的 2 件改为 8 件，再模拟 503 后重试，验证两次请求的配方及请求 ID 完全一致。

## 战斗与声音

技能横幅的第二行文字实际受矩形高度裁切，须以 TMP 生成的可见字符复验。预禁闪光限制在当次选中项，避免邻格被强白光覆盖。结算中心的胜败提示和闲置平局标签从显示代码、预制生成器及绑定中移除，保留结果主体。

公开实机 [2022-10-29 光泰温对局](https://www.bilibili.com/video/BV1Nv4y1D7F2/?t=216) 的 03:37.2–03:38.2 在受晕角色身前显示「無法行動」，随后切换行动者。左下人物栏在此片保持前一名角色，03:38.9 才切到下一名。这段支持提示及约 1 秒停留，无法支持受晕者头像切换。项目按用户明确要求切到受晕者，再等待约 1 秒。四帧及 0.1 秒连续采样在 `.artifacts/equipment-manage-followup/reference/stun-public/`。公开视频倍速、角色皮肤和精确游戏版本未知。

二维界面音频取消时按非缩放时间淡出 0.20 秒。根 Canvas 点击、无 Canvas 的按钮、召唤演出及获得语音、合击提示、灵魂燃烧、竞技场门和结算已接入。每次播放单独保留其音量与 Foundation 音频句柄，关闭窗口可立即释放预制和场景数据。角色普通语音的 `VoiceService` 和 FMOD 原生事件由相应服务管理，本轮未接入。旧 Windows 客户端仍为 R35，本轮 Common 与 Bootstrap 变更须随新母包分发。[通用规范](../development/project-standards.md) · [母包边界](../development/hot-update.md)

在隔离 Unity Editor 从 Win64 离线资源包加载项目结算配置 `battle/online-transition`。释放窗口句柄后，该配置已原生卸载，胜利音效仍在播放。取消后约 65 毫秒的中段采样显示音量正在下降，淡出结束后独立音源被销毁，AudioClip 也随最后一个句柄释放。两个重叠点击同时淡出时，新 Canvas 的声音保持独立音量。原实现并发点击关闭回归 0/2，修正后含关门取消、合击及胜败结算的 PlayMode 回归 15/15 通过。此项读取 AudioSource 的播放状态、音量和原生对象生命周期。[离线验收回执](../../.artifacts/equipment-manage-followup/stun-clock/packaged-ui-audio-final.xml)

## 召唤小人清晰度

R35 签名包中 `n_bibleo` 为 1707×511，`n_biblika` 为 491×1264，均为单 mip 的 RGBA32，解码像素与项目 PNG 一致。头部有效块分别只有约 168×170 和 164×161 像素。1080p 头部放大约 2.60、2.83–2.85 倍，4K 达约 5.21、5.67–5.69 倍，取决于骨骼形变。此处清晰度受有效源像素和放大倍率限制。本轮未新增高清源图。签名原包和采样记录在 `.artifacts/summon-fidelity/`。

## 运行复验与发布

Unity 2022.3.62f3 D3D11 最终联合图形回归 16/16 通过，0 跳过，包括管理装备的训练服真实事务、英雄搜索筛选、神器正文、GM、眩晕与胜败终态及召唤取消音频。复合换装确认的两行备注在原实现触发截断，`transfer-red.xml` 记录实际失败。确认窗现按属性行与备注自然行高分配空间，新增用例验证替换、转移说明全部可见，取消后两名英雄的装备和库存版本均不变。另跑受影响的 4/4，覆盖同一管理流程、英雄排序、普通装备穿脱和神器长文，和联合验证有重叠。编辑模式装备、神器和 GM 契约回归 14/14 通过。证据分别为 `.artifacts/equipment-manage-followup/accepted/playmode.xml`、`equipment-recheck.xml`、`editmode.xml`。

最终无损截图在该 `accepted` 目录，管理页包括选前、候选、筛选弹层、确认和提交后。候选额外复拍 1280×960、1920×823，常规游戏区使用 1478×720。截图中的训练账号有两件武器候选，画面不填充虚构库存。英雄与神器对比图在 `.artifacts/equipment-rereview-hero/`，独立模块回归 PlayMode 4/4、EditMode 4/4，与联合验证有重叠。

上面所列测试不代表已分发 Windows Player 验收。本轮没有新打包或切换签名发布入口，当前玩家安装仍以 R35 记录为准。原片的总战力、推荐配装和普通装备强化尚无完整项目逻辑，GM 当前支持六部位及现有的速度、暴击套装。新增其他套装需要共享计算与客户端一起实现。
