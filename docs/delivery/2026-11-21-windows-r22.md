# Windows x64 本机试玩包 0.1.23 / R22

## 为什么需要强更

本次客户端内容来自 `464835e5`。0.1.22 母包的归档基线是 `7b9d6ea99e4b4a05b2939d7f400b2610`。读取该归档中经过 IL2CPP 裁剪的 `AstralOath.Client.Common.dll` 元数据，已有的 `FocusedRosterScroll` 包含 `Bind`、`PlaceCard`，缺少本次使用的 `LayoutCards`。装备槽和强化角标新增的四个公共类型也不在旧母包中。R22 的页面绑定会直接调用这些代码，需要将新原生播放器与匹配的签名内容一起分发。

R20 和 R21 使用同一 0.1.22 母包。该次对预禁第二组立绘的修复位于竞技场业务程序集，可由签名热更交付。Windows 0.1.21 升 0.1.22 时也曾更换母包。是否需要强更由各平台已分发母包的实际内容决定。[上一版构建与验收](2026-11-20-home-and-arena-ui.md)

## 构建和复现

使用 Unity 2022.3.62f3，从提交树及 Git LFS 哈希核对隔离工程的 22,933 份输入。运行 `Tools/Invoke-Unity.ps1 -ProjectName UnityWindows -NoSync -Mode Windows -Development -DevelopmentHttp -Minimal -AppVersion 0.1.23 -AndroidVersionCode 1 -ContentVersion 22`，同时传入本机 5295 的清单、签名地址和已有公钥配置。完成后，在同一镜像调用 `Tools/Content/Package-Unity.ps1` 签名，以独立的 `Tools/Content/Release.ps1 -Action Verify -ProtocolVersion 1 -SchemaVersion 3` 验签。

最小母包对应 `StandaloneWindows64`、x64，内置内容版本为 0，基线为 `25cda4dbafde4770b98611b1323689a1`。归档中确认四个装备槽与角标公共类型、滑条的新布局方法均存在，YooAsset 构建报告包含英雄、RTA 页面及两个公共预制体。签名 R22 的 98 项内容共 2,142,929,287 字节。游戏服务使用 7728，R22 内容源使用 5295，已分发的 R21 内容源继续使用 5294。

本机交付目录是 `.artifacts/ui-nov21/delivery`。解压便携包后双击 `启动试玩.cmd` 启动服务和游戏。首次安装 R22 内容后按提示退出，重新打开 `AstralOath-Play.exe`；重复打开可多开。游戏服继续使用规则 17。随包的 MySQL 和本地管理脚本复用本机当前用户的试玩库。用新目录和空数据在独立回环地址 127.0.0.2 实测随包运行时、数据库和服务首次启动、健康检查及有序关闭通过。

## 交付验收

- 完整压缩包为 `.artifacts/ui-nov21/AstralOath-Windows-x64-0.1.23-R22-7728.zip`，共 1,170 个文件，2,020,411,950 字节。解压到含中文和空格的目录，逐文件比较哈希通过。ZIP 的 SHA-256 是 `2aaef3666b8d050d310a2ff473e185a32cfb54e69c21439cc8502b2ea22e81b2`。
- 从实际解压目录以 `-batchmode -nographics -astral-demo-echo` 启动 IL2CPP Player。新基线初始无缓存，从 5295 取得签名内容，通过 HybridCLR 加载 `AstralOath.Client.FoundationDemo`，报告 `ASTRAL_CONTENT_ACTIVE version=22 recovered=False`，从 7728 收到回包序号 6。提高最低版本后再从多开 EXE 同时启动两个无窗口进程，二者各自激活 R22，并收到回包序号 7、8。记录在 `qa/native-headless-first.log`、`qa/dual-headless.json`。
- 切换前 7728 最低版本仍是 0.1.21。确认新包可用、房间目录为空后，使用原有管理脚本停止并重启同一套服务，把当前进程和下次启动的最低版本设为 0.1.23。切换前的测试会话和三个持有英雄实例在切换后逐一读回。实际版本接口返回 0.1.23。向选服接口传 0.1.21、0.1.22 均收到 HTTP 426 `client_update_required`，传 0.1.23 后进入身份校验，无凭证返回 HTTP 401。记录在 `admission/after.json`、`admission/realm-check.json`。
- 普通窗口已启动，桌面操作在点击登录前停止。本轮没有目视验收旧客户端的强更弹窗、新客户端的下载重启提示或普通窗口内的英雄页。两份客户端的启动与网络回包采用无窗口模式验证。英雄页的图形回归见[英雄页验收](2026-11-21-hero-layout-and-navigation.md)。本次发布范围为本机 Windows 试玩环境。
