# 英雄详情、装备槽及页面切换复核

## 视觉依据

用户反馈的三个场景分别是三名英雄选到最后一名、1040×1108 近方窗口的装备框和符号分离、标准横屏中拉斯立绘偏小。原版英雄页依据 2026-11-17 的本机录屏 `Screenrecorder-2026-11-17-22-21-00-778.mp4`。该文件的录制日期已知，未确认公开发布日期及播放倍速。

- 02:18 的英雄页中段与竞技场选人录像对齐到 720 高时，蓝色焦点牌面的实色高度约为 89 像素，两名排在前面的英雄各露出约 56 像素。实际贴图 `hero_bg_normal`、`hero_bg_selected` 的透明留边占据 112 像素总高度的一部分。三人短列表的末行来自用户复现，参考录像本身展示长列表中段。[选人时刻和光效依据](../development/arena-draft.md#角色滑条与引导光复核)
- `wnd/unit_bar.csb` 中姓名字号 24，节点缩放 0.85，换算为 20.4，使用常规字重。修订前截图中文笔画实高约 23 像素，修订后约 18 像素。等级分支使用 `hero_lv_0..9` 和 `hero_lv_max`。战力排序参考画面中的橙色战力数值属于另一个节点。卡片头像从 y=10 到 y=99 使用源图宽高比。
- 约 02:12.5 的菲奥雷托换装画面和原包 `c1074_s01` 的领口、腰带、头部匹配，比例为 0.795–0.805。另以永劫漂流者鲁特比 `c2069` 的眼镜和靴子独立复核，比例约 0.80。装备页按 720 设计高显示 900 个骨骼单位，骨骼原点在页面底部、中心右偏 20 设计像素。旧版按每个角色自身包围盒尽量放下全身，拉斯每 100 个源单位只占 57.9 个设计像素。召唤近景沿用其独立取景。

## 固定组件

英雄详情的标题、信息栏、装备和操作区都保存在 `HeroInventory.prefab`。详情中有 7 个固定槽位，背包的英雄行模板中有 8 个，包含预留的专属装备槽。15 处都引用同一份 `EquipmentSlot.prefab`，其内预置底板、空槽符号、物品 Image 及 `NotificationBadge.prefab`。角标支持隐藏、纯红点和带强化等级三种显示。神器使用当前持有快照提供的装备实例及其强化等级。普通装备实例的服务端数据尚未接入。英雄列表的行数随库存变化，运行时复用卡片模板。

原 `unit_detail.csb` 的普通槽为 98×99，符号为 33×33，神器槽为 123×137。旧版的保留比例只作用于绘制图案，子节点却相对拉长的矩形定位。测试在 1040×1108 复现旧版武器框承载矩形的实际宽高比 0.457，源框约为 0.990。验收包含从近方屏切回宽屏、两列装备与右侧列表的空间、模板实例来源和空槽/装备/红点状态重绑。

## 数据与目录

进入竞技场大厅和英雄页均使用 GameHome。此前页面资源已在同一登录中常驻，持有快照会在 30 秒后过期，首次请求失败后的成功重试也只存在于当时打开的页面。修订后，英雄和神器使用分开的会话缓存。一次登录只做必要的首读，发布写请求后作废受影响的数据，成功重读可复用。首选英雄的解析数据在登录黑屏阶段准备，已访问立绘的解析结果可随会话复用。隐藏及关闭页面照常解绑事件并释放渲染实例。房间席位和战斗判定继续查询权威服务。

竞技场“更新目录”手动刷新并发查询当前房间和房间列表，关窗取消等待，房间列表复用未变化的行并保留滚动位置。每轮读取固定延迟 120 毫秒的测试中，手动刷新从 256 毫秒降至约 122 毫秒。本机 7728 空目录的暖刷新约为 1–2 毫秒。未在该条件下重现秒级等待。[实测条件和边界](../development/arena-lobby.md)

## 验收

- Unity EditMode 四项检查了全部 15 处嵌套关系、公共依赖、数字字形及空槽、已装备、纯红点和 `+12` 状态之间的切换。英雄和 RTA 滑条均在预制中预挂 `FocusedRosterScroll`，打开时复用该实例，关闭时禁用。两份公共预制体的依赖均未进入业务模块。
- Unity 图形 PlayMode 的十项用例覆盖真实主页入口、三人列表末项、等级 1/59/60、立绘和引导光。截图覆盖 1920×1080、1600×1000、1040×1108 和 2520×1080。近方屏右侧装备与名册互不遮挡，底部晕影铺满整个窗口。实拍存放在 `.artifacts/arena-guide-review/root/presentation`，原片与同款角色的配准图在 `render/equipment-source-framing.jpg`。
- 会话缓存 11 项 PlayMode 通过。在控制响应时间的本地测试中，竞技场等待 30.25 秒再开背包和英雄，旧实现累计读取英雄库存三次，修改后只读一次，12 个共享资源的加载次数均未增长。首次神器请求失败时，修改后在进入页面时重试一次，此后复用。还覆盖账号隔离、写入作废、延迟旧应答和窗口取消。`cache/before.xml` 与 `cache/final.xml` 分别记录旧版复现和本次结果。
- 本机 7728 使用一次性访客实际获得八件神器，验证双列横卡、详情大图、装备与卸下、出售、强化及服务端回读，两项通过。真实 RTA 的预选和滚动吸附通过。测试记录在 `.artifacts/arena-guide-review/render/artifact-live.xml` 和 `root/rta-online.xml`。
- 同一服务的双会话 RTA 从主页完成选禁、进战、权威指令和退出，返回时逐帧检查未显示上一轮选人页。首次整流程在等待第二组预禁时超时，单独复测保持同一断言，记录两组实际播放后全程通过，耗时 46.88 秒。首次超时原因未确定。证据在 `render/rta-return-trace.xml`。本机服务未开放开发专用的神器试战路由（HTTP 404），该入口的切场景用例未通过。
- 已分发 Windows 0.1.22 / R21 保持原版本，以上为本轮源码和预制体的 Unity 验收。本轮涉及 Common AOT，发布到 Windows Player 需要新母包。
