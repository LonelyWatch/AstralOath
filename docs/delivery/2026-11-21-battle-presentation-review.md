### 治疗与前后排遮挡

国服秋季赛 P2 的 08:04.50–08:05.20 同屏出现绿色回复光、前排轮廓、行动提示和伤害数字。用户提供的近景另可见治疗绿十字与血条。原片没有给出粒子间的数值层号，录像发布日期、可见倍速和此处英雄形态未确认。[P2 对照段](https://www.bilibili.com/video/BV1n7x96DETN/?p=2&t=484)

`heal_hp_01.cfx` 只有一个粒子 primitive，没有显式 `z` 或 `globalZ`。`heal_cross_01` 的原始混合是 ONE / ONE_MINUS_SRC_ALPHA，`cross_02`、`pati_01` 和 `flash` 是 SRC_ALPHA / ONE。工程将所有治疗粒子放在同一排序组内，软光先画，实色十字后画。组在受疗者之后、下一排身体之前绘制，血条和治疗跳字仍在 HUD Canvas 上。组内次序与深度间隔属于工程拟合。

复现时使用战场原有深度为 54、55 的两名角色，把前排移到与后排身体重叠的位置，只对后排回复。在相同相机、相同粒子时刻（0.24 秒）的 320×320 图中，修复前受影响的前排不透明像素为 22,634/22,634；修复后为 46/22,634，受疗者的身体仍有绿光。该计数选取单独治疗时 RGB 至少一项变化超过 40、前排 alpha 至少 254 的像素，再统计叠加前排后 RGB 仍有任一项变化超过 5 的像素。对照图在 `.artifacts/summon-result-r23/heal/healing-depth-comparison.png`，原片裁图在同目录 `0804-detail.jpg`。

## 竞技场结算

用户提供的国服秋季赛 P2 `2.3060-3091_43325065328.mp4`，1920×1080、30 fps。文件未注明发布日期，片段倍速未确认。08:45–08:49 可见中央胜利剑徽先展开，再显示左侧本方头像、好感度与右下两枚按钮。固定源 `wnd/result_base.csb` 给出胜负锚点、高度、四个头像位置、好感度和战斗结果按钮。胜利和失败 CFX 共用 `eff_pvp_outro_victory.scsp`，各自的 `*_instant` 段长约 1.667 秒，然后播放自己的 `*_loop`。本段原录像仅验证胜利，失败取自固定包。视觉样本保存在 `.artifacts/summon-result-r23/result/`。

竞技场终态快照到达且最后一个动作演完后显示 `BattleResult.prefab`。四个槽位由本机视角的参战阵容填充，使用圆形 `_s` 头像并固定显示当前约定的 1 级爱心。战斗结果按钮读取双方终态生命和回合，确认按钮调用既有离场入口。练习赛没有权威积分或奖励字段，界面省略了排位录屏中的积分和物品区。平局显示独立标题。Unity 图形回归分别打开胜、负、平局，点开双方实际生命值，再关闭详情并确认。原素材依赖由 `ImportBattleResult.py --check` 校验。

## 本方提前选技能与权威回包

`ArenaCommandPlaybackTests` 用实际竞技场入场、HUD 按钮、联机序列化／解码和共享战斗规则构成回归。夹具在进程内接管 HTTP 请求，控制回包时刻。双方演出等待期的时钟字段有效，`deadlineUnixMilliseconds` 为 null。旧版此时本方技能不可选，可在 `result/command-before.xml` 复验。

送出后技能组和燃魂按钮同帧隐藏，拦截重复点击。返回权威 `SkillOnCooldown` 时保持场上动作、显示原因并恢复选择。第二次用同一技能选择目标，原规则实际接受并返回事件后才播放。HTTP 401 单独走会话终止。XML 位于 `.artifacts/summon-result-r23/result/`。本项验证的范围是客户端收发与画面，真实 7728 服务演练单独记录。
