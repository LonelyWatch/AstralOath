# 召唤后英雄库存与伊赛丽亚 UP 预览

## 登录后连续召唤

R24 在登录过渡时取得英雄和神器库存，但发出任意召唤 POST 及其结束时都会将两份快照设为空。连续召唤后第一次打开英雄页会进入加载分支，并重新请求整表。复现时从同一登录的 Foundation 导航打开英雄页，记录 `GET /api/inventory/heroes` 次数，并检查新英雄实例 ID。

本次改用召唤回执及保管箱领取结果。实发英雄以服务端回执中的实例、模板和星级加入列表，初始等级按发放规则为 1。实发神器以召唤来源、初始强化等级 0 入库。新实例按获得顺序追加，重复回执或实例不重复计数。暂存奖励在领取成功时加入。单纯查看历史回执只回放，避免把后来出售的神器重新加入。明确拒绝保留缓存，写入结果未知、首读尚未完成或数量超过缓存容量时启动权威校准。其他登录拥有独立缓存。

Unity PlayMode 用例 `SettledDrawsUpdateResidentInventoriesBeforeTheHeroPageOpens` 在旧代码首次抽卡后测得缓存为空。修复后检查连续抽取、重复实例、暂存、抽到神器和实际进入英雄页，英雄整表 GET 始终为登录时的一次。复测另含余额不足拒绝、领取暂存英雄和再次登录的隔离。

参考为用户提供的《全角色大招动画合集【4K60FPS_日语cv】》普通自然属性伊赛丽亚段，13:28.6–13:38.6。发布日期和游戏内倍速未确认。位置按 640×360 等比图测量，项目预览敌人为史莱姆，参考片段为木桩。[同期战斗分镜记录](2026-11-21-iseria-s3-r24.md)

召唤页实际播放 17 张 JPEG 图集中的 269 帧，每秒 24 帧。R24 的实时战斗镜头修复没有更新已烘焙的这套帧。将两张用户附件与解码图集匹配，旧第 68–70 帧即有黑白水平分界，旧第 178 帧最接近剑贴底的截图。两种问题都可在进入 UI 前从图集复现。

从修正后的战斗演出重录并重打图集。旧第 69 帧上下取样带的平均亮度为 0 和 255，新片两处同为 231，保留整屏短闪。从主页进入召唤，切池、返回并再次打开，已两次验证实际播放这组新帧。
