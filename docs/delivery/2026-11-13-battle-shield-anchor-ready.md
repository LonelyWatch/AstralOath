# 护盾挂点与入回合动作复核

## 根因和通用规则

- 普通盾在 `cs_player` 的 `cs_eff_bone` 字段绑定 `shadow`。绮世原 `model/kise.scsp`（SHA-256 `0d3005cd4467d770e4085ecfef42fcc10d6ae9f8fe30faf86521a13fdf3201ae`）的该骨骼在 `idle` 为 X=-36.80，在 `b_idle` 为 X=+74.05，`b_idle_ready` 连接两者。旧 View 只在创建时从场景的地面影子取偏移。绮世普通战斗待机相差约 74 个源像素，缩放、镜像后与截图偏移方向一致。拉斯、亚敏和席可也在待机骨骼中有独立偏移。
- 护盾继续归角色身体 Renderer 所有，每帧在当前骨架空间读取 `shadow` 位置，应用 `stse_protect.cfx` 自带 Y=20 源像素、比例 1.5 与层序。镜像、移动、变倍和遮罩由身体继承。场景影子位置作缺骨骼时的回退，避免地面影子独立运动时拖偏护盾。仅采样位置，骨骼影子宽度不参与光圈缩放。技能图显式世界影子挂点保持原有用途。
- 十名角色的源骨骼同时含 `idle`、`b_idle_ready`、`b_idle`。绮世 `b_idle_ready` 的 302 条变化骨骼轨首值与 `idle` 对齐、尾值与 `b_idle` 对齐。入回合动画单次播放，之后保持战斗待机，非当前回合回到普通待机。重复快照、受击与技能恢复不重新触发已消费的入回合动作。准备尚未开始时由正在控制姿态的演出先完成。兼容没有有效准备段的旧模型。
- 当前结论来自只读解包骨骼及 Unity 实测。原作运行时控制脚本与安洁莉卡、梅赛德丝额外待机附属效果未纳入。

## 验证

- 修复前，Unity 中十名角色在超过准备动作时长后仍播放 `b_idle_ready`。绮世我方测试槽的护盾离预期源骨骼挂点约 0.395 Unity 世界单位。
- 针对性 Unity PlayMode 10/10。覆盖绮世双朝向、骨骼三个采样位置、角色离地、缩放、镜头变倍，另有护盾吸收、隐藏及再显示、实战回合准备一次、夹攻和全屏演出。实帧位于 D 盘 `.artifacts/shield-anchor/kise-barrier-both-facings.png`。
- 护盾源导入验证通过。清单仅更新上轮转换器修改后过期的校验值，原始与转换后的护盾资产哈希保持一致。
- 最终 Unity EditMode 480/480，覆盖十名英雄的入回合单次播放、同回合去重、演出占用、受击与退出恢复，旧模型缺失或零时长准备段也通过。Windows 与 Android 客户端包本轮未重建。
