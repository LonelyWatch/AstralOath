# 主页、召唤与模拟战界面复核

## 召唤获得演出与结果卡

在 1824×1120 的窗口复现席可的获得演出。大立绘的绘制区域实际投影约为 1736×1736 像素，原离屏纹理固定为 1024×1024，显示端再次放大 1.70 倍。小模型所在的演出层从 1173×720 放大到 1824×1120，相当于每个方向再放大约 1.56 倍。两处各自按画面中的实际像素申请离屏纹理，并在窗口尺寸变化后调整。单边上限取硬件限制与 4096 的较小值，超出上限仍保持比例。

通用检查顺序为原贴图、导入尺寸、骨骼附件对应的图集区域、离屏目标、最终绘制尺寸。席可两张图集解码后与导入源像素相符，脸部附件约 150×131 像素。修复后在 1824×1120 和 1368×840 的图形 PlayMode 中复核实际采样密度；超近距离仍受原画细节限制。复现与截图在本机 `.artifacts/summon-pixel-density`。

十连横卡原来将不同宽度的头像映射到固定 Rect。源布局 `gacha_unit_bar.csb` 将头像以右下为锚点放在 (352, 1)，等比缩放 1.1，再由卡面裁切。70 名英雄的横头像宽度有八种，席可的 `c1004_l` 为 190×89。已分别验证席可、拉斯、另一张宽头像和神器结果卡。见本机 `.artifacts/summon-card-portrait`。

结果页再次召唤按钮按 `gacha_summary` 的图层、价格底板和间距还原。用开发账号执行十连后，从价格文字处按下、松开，核对普通态与按下态。报价为 50，单抽重复报价为 5。剩余 10 书签时点十连确认，弹出“材料不足”，可取消返回原结果，余额保持 10。两个独立连接同时用同一账户的 60 书签发起十连，一个收到 10 件奖励，另一个收到 409 `insufficient_bookmarks`。重放成功请求仍只扣一次，最终余额 10。红绿结果在 `.artifacts/ui-nov20/materials-red.xml` 和 `materials-green.xml`，并发记录在 `.artifacts/summon-card-portrait/real-concurrent-draw.json`。

## 主页首次打开

登录后以黑色遮罩覆盖到主页准备完成。“更多”、英雄与背包共用的界面、召唤界面各准备一份隐藏视图。首入所需的七个资源地址各加载一次，账号的英雄、神器和召唤状态并行读取，沿用当前登录身份。回归通过正式按钮连续打开三个入口，新增资源请求和新增 GET 均为零。该结果针对新鲜预读快照；超时、账号数据变更或跨免费召唤重置时会再查权威状态。黑幕的失败与取消路径在 `.artifacts/home-preparation` 中复核。

## 英雄、神器与模拟战

### 英雄目录

英雄详情原来用普通列表内容高度显示带偏移的叠卡。少量英雄时，滚轮命中列表却没有足够的滚动范围；停止移动后也不会将焦点行同步到详情。两处入口现在使用同一个 `FocusedRosterScroll`，为末行保留抵达焦点线的余量。英雄详情按持有实例 ID 区分同一模板的不同英雄；模拟战沿用权威候选与禁用规则。实测包含三名同模板英雄、鼠标滚轮和按住拖动、释放后的末行，以及空列表和不可选行。

### 神器背包

比对本机 `.artifacts/inventory-reference/bag-artifacts.png` 与用户截图，旧列表使用小方格，右侧放大了列表用的窄横幅。现按双列展示装备徽章与横幅，右侧详情使用竖卡及独立属性、技能区。核对 42 套素材的三种用途，分别为 116×128 徽章、260×92 横幅和 378×598 竖画。于 1478×720、1536×960 两种画幅核对六件真实持有的神器，并验证连续锁定、解锁、取消材料选择、出售和确认强化。截图及图形 PlayMode 记录在 `.artifacts/artifact-bag-layout`。

### 蓝红光效

原始布局 `pvplive_ready.csb` 将蓝、红光的原点放在选人区的 (274, 326) 与 (722, 326)，源透明度为 127/255。倒计时弧条有自己的锚点。原界面只生成了弧条及卡槽确认效果，导致选人期间中央两侧缺光。选人期间使用 `effect/ui_livepvp_arrow_blue.cfx` 和 `effect/ui_livepvp_arrow_red.cfx` 的 `intro` 循环，两者的亮度周期约为 1.33 秒。蓝红分别来自各自的原始骨骼，红侧镜像已包含在骨骼附件中。

运行 `Tools/Arena/ImportDraftFeedback.py --check` 核验 50 项效果闭包产物与源文件溯源。通过 7728 进入双人模拟战，分别在己方和对方回合采集的图像保存在 `.artifacts/ui-nov20/draft`，包括首轮选人和对方等待画面。

完整联机复验还捕获了预禁揭示跳组。第一组已显示 0.793 秒，此时战场预加载产生 1.121 秒长帧，旧逻辑直接越过两组和淡出的结束位置，清掉了尚未绘制的第二组。揭示动画现每个已渲染帧最多推进 0.10 秒。通常帧率下仍按原来的 0.83 秒一组、0.18 秒淡出播放；服务端选人截止时间独立计算。复现数据见 `.artifacts/arena-return-integrated/timing.log` 的 `PAIR_TICK`。

按同一帧耗时序列回放，第二组两张立绘均绘制出非透明像素，完成灰化与收起。两份独立镜像分别完成了 7728 双人选禁、战斗和结算返回，耗时 50.56 秒与 45.91 秒，最终运行日志均无 `TaskCanceledException`。并发图形组合曾在等待揭示底栏时超时一次，Windows 构建镜像的独立复跑已通过。记录为 `.artifacts/arena-preban-stall/final.xml` 和 `.artifacts/ui-nov20/r21-client-online-green.xml`。

### 对局结束返回

双人真实对局复现了结算页切回选人页的中间帧：旧流程先卸载战斗场景、恢复主页 Canvas，再通过异步通知离房并切到目录。新流程在战斗仍然遮住底层时等待目标页面准备完成，再卸载场景并恢复底层显示。结算仍遵循模拟战目录已有的房间恢复逻辑。

另用延迟响应复现了目录刷新期间关闭页面会把页面取消向上抛出。现在由发起查询的目录处理自己生命周期的取消。截图中的异常类型为 `TaskCanceledException`，该次用户进程的完整调用栈没有保留下来。真实双人对局从登录、选禁、布阵、战斗到结算返回已通过，逐帧检查覆盖退出通知与画布渲染。旧版红例和修复结果见 `.artifacts/ui-nov20/return-online-{red,green}.xml`，延迟响应、房主及客席的独立用例见 `.artifacts/arena-return-focused`。

另外复现了两个网络边界。离房请求失败、玩家仍在旧房间时，登录导航记录房间 ID 和已经退出的选禁 ID。房间轮询收到旧局快照时保持房间页，同房下一次选禁仍可进入。查回当前房间返回 204 时即可显示大厅，房间列表继续在大厅内加载，期间可以返回主页。对应旧版两例均失败，本次包含这两例的图形回归 12/12 通过，见 `.artifacts/arena-return-edge/{red,green}.xml`。

## Windows 本机交付

Windows x64 0.1.22 使用新 Common AOT，最小母包的基线为 `7b9d6ea99e4b4a05b2939d7f400b2610`。R20 收入结算返回修订，R21 在同一基线补上预禁跳组修复。原生多开入口为 `.artifacts/ui-nov20/delivery/AstralOath-Play.exe`，游戏 API 使用 7728，签名内容使用 5294。

R21 已用公钥独立验签，协议 1、schema 3，清单共 98 项，内容总量 2,146,831,316 字节。对比两份签名清单，R20 到 R21 有 10 项新增或变化，总计 107,783,168 字节。已用同一母包从空缓存执行下载、校验、退出并重新打开，进入了 R20 主页；实际 R21 更新界面显示增量为 102.8 MB，验证完成后提示退出。记录在 `.artifacts/ui-nov20/qa`。

退出后分别从试玩脚本和原生 EXE 打开两个普通客户端，两个窗口均进入可操作的主页，先关闭一个窗口后另一个继续运行。两份日志分别记录了 `ASTRAL_CODE_BOOT_OK release=21 recovered=False` 和 `ASTRAL_CONTENT_ACTIVE version=21 recovered=False`，见 `.artifacts/ui-nov20/qa/R21-normal-{first,second}.log`。另开两个独立进程访问 7728，服务端响应序号分别为 4、5，详见同目录的 `two-echo.json`。
