# 战斗信息条、S3 背景与待机衔接修复

日期：2026-11-13。主工程 `D:/UnityProjects/AstralOath`；源目录 `D:/sevenepic` 只读。本轮只修客户端表现，不修改服务器权威战斗、伤害、技能数据或随机数。

## 已定位的问题

1. `SetCinematicVisible` 把 `Unit Status` 与技能组一并关闭；而该回调也会由普通 CAM/BGHATCH 触发。现仅控制技能/Burn，生命、等级和状态继续显示；真正全屏 CUTIN 通过幕布及画面排序遮挡，暂停仍在最上层。
2. 拉斯/梅赛德丝 S3 源 STG 确有 BGHATCH 速度线，不是导错背景。原始 PNG 的透明度承载线条强度，Unity Shader 只读 RGB，又使用不匹配的混合因子，导致透明区域变成亮条块。修复三角色共用 Shader 的采样/混合，不更换图片、不调角色特判参数。详见[像素与来源审计](2026-11-13-hatch-alpha-audit.md)。
3. 拉斯受击尾姿态与普通 `idle` 一致，却直接切换到另一姿态的 `b_idle`，中心骨骼瞬间变化约 62 源像素。原始 `b_idle_ready` 并不适合所有技能尾帧，例如拉斯 S3 尾部不在其起点，因此不按名字强行插入过渡动作。

## 通用修复与边界

演员回待机使用 0.15 秒混合，属于项目视觉衔接参数，尚未以原版连续帧证明具体时长。旧版 Spine 的原生混合只覆盖目标已有动画键；实测单纯加混合仍有骨骼/附件/绘制序残留。因此适配层还必须保证目标遗漏的状态收敛到独立播放时的 setup 基线，并保留已完成动作的尾轨用于过渡。不能用末尾强制 Seek 或世界位置补偿隐藏问题。未键连续量按混合权重恢复，附件/翻转/绘制序在中点离散切换；中点也是项目策略。已键曲线及事件保留，迟首关键帧只在进入首轮前补 setup，后续循环保留原运行库行为。实例元数据缓存与每次播放包装分离，使用实例 DefaultMix 避免切换关系字典无限累积。

源骨骼和官方运行库不改，适配只在项目桥接层。共享不可变解析缓存保持，动画状态及补充混合数据属于各实例；关闭释放、暂停、Seek、事件和后续动作不参与权威结算。依据 [Spine 官方混合说明](https://esotericsoftware.com/spine-applying-animations)区分逐属性混合与离散附件/绘制序切换；2.1 细节以锁定源码和实际回归为准，不能把新版 API 假设直接套入旧核心。

Core 骨骼适配属于 AOT，本次修复需随新母包发布。Shader/内置 Resources 同样需要对应平台构建；本轮 Windows Mono 诊断包不能代替正式 HybridCLR IL2CPP 母包或 Android 验收。
