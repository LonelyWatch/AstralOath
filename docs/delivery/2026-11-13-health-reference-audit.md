第一组图能直接确认：目标受击纵向位移时，等级、HP 与状态图标组仍位于目标上方并随其上下移动，不是停留于原始站位。火焰、击中特写、白色闪屏及镜头返回过程中，信息条依然参与画面；角色在白闪中难以辨认时，仍能辨认条组。这补足了“只观察静态条”的证据缺口，支持实现必须在骨骼、角色位移及相机更新之后逐帧投影。该接触表不足以单独量化 UI 与角色的缩放比、是否存在缩放限幅或确切源 offset，不能将“跟随位置已确认”写成全部缩放策略已测定。

第二组图能确认：最后攻击结束、伤害数字出现后，目标经历深色轮廓/黑化，再出现烟雾或碎片状淡出，后续由 `Victory` 图案和全局暗幕覆盖。按该片段采样窗口，黑化变化约在 **3041 秒附近**，烟雾/碎片样淡出约在 **3042 秒附近**；这些只是便于回放定位的近似时间点，**不是独立测得的精确动画时长**。本次不能分离所有局部黑化与胜利全局变暗的贡献，也不能从被 `Victory` 遮挡的尾部证明死亡何时完全结束；因此不给出“原作黑化固定 X 毫秒、消散固定 Y 毫秒”的数值结论。

实现可据此采用事件驱动的“死亡状态已确认 → 保留末次姿态/受击收尾 → 渐黑 → 消散 → 清理”表现阶段，并配置参数继续对照；不得因黑化/消散回调改变权威死亡状态，也不得把全场胜利暗幕直接当成单体死亡着色。当前样本证明该表现方向与原画面相符，不证明项目实现的所有时长、粒子和渲染细节已逐帧一致。

## 建议的可扩展实现约束

1. HUD 位置取当前 Spine `top` 世界位置，经实际战斗相机和当前 Canvas 转换得到；跟随必须在动画求值、Actor 位移、镜头更新之后执行。坐标链只投影一次，包含场景相机震动与缩放。文字/图标保持朝向正常，不随角色水平翻转。
2. 每种 HUD profile 保存原生布局尺寸、锚点名、明确的源坐标偏移、可视缩放策略和证据状态。骨骼中根缩放与 Actor/presentation 缩放要区分；不能重复乘 `root`。没有源 offset 时给出可配项目初值并保留标定记录。
3. 刻度策略独立于权威 HP。普通英雄 profile 默认采用本轮官方样本验证的十等分百分比，九道内部线，50% 中线与短刻度分别配置，覆盖整个 HP 框。保留 Boss/关卡专用 profile，不能将 `HP-per-mark=1000` 作为通用默认。只在护盾显示范围/宽度/profile 等影响几何的输入变化时重建刻度，避免每帧分配对象；固定百分比时单纯 maxHP 数值变化不必重建线数。若将来因最小像素间距简化刻度，注明属于项目可读性规则。
4. 权威血量、绿色显示血量、红色 trailing 血量分开。战斗事件立即记录最终真实值，受击演出仅驱动展示目标。连续多段伤害从当前显示状态平滑重定向；暂停、调速、重播、切换 Actor 和对象池回收都要重置明确。不得从红条动画完成回调结算伤害或死亡。
5. 护盾、治疗、最大生命变化、复活、濒死保命和 Boss 多阶段必须有独立输入；不能将所有变化都视作单调扣血。当前未实现的路径明确列待验，不让绿条缓存跨角色残留。
6. 普通攻击、移动、受击及场景内技能保持血条；确实覆盖整个画面的 CUTIN 可以由画面遮挡，但不能把任意技能状态等同于隐藏 HUD。死亡清理由确认的战斗死亡事件驱动，与黑化消散展示生命周期分离。

## 后续对照的最小测量集

需对同一当前版本、同一分辨率记录可见总 HP 和无护盾时的分隔数量，至少覆盖低 HP、普通输出、高 HP 坦克、普通敌人和 Boss；再比较受伤后、获得护盾后及 maxHP 改变后的刻度，避免把“格总数”和“剩余绿色格数”混为一谈。镜头远近、人物位移、受击、最后一击返回和 CUTIN 前后分别录制，以确定根偏移、可视缩放和尾条时长。每项保存来源 URL、发布日期、时间码、数值及“观察/推断/确认”状态。

本审计已实际完成 2026-11-08 官方视频这些普通英雄 HP 样本的像素测量，并查看受击跟随与死亡演出的连续帧。未声称覆盖全部模式，也未声称已测出精确动态时长或完成 Unity 运行视觉验收。其余项目由实现验收记录接续。
