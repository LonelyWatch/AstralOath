# 模拟战房间延迟、断线回收与界面复核

## 头像与表情面板

房间原先将 112×112 的 `face/c1001_s.png` 放大后用于对阵头像，Unity 又对头像及头像框应用纹理压缩。当前头像由 `face/c1001_su.png` 的原始像素裁出 140×140 区域并水平翻转以保持原头像朝向。对阵头像、成员、聊天共用 Common 的头像预制体，由房间模板指定无压缩头像与头像框。原始 3.8 立绘的单独头部图块没有提供更高的实际脸部像素密度。窗口放大至 4K 时仍受原画像素数量限制。

对照用户提供的国服录屏 1:39.50 至 1:42.20。原版 `wnd/chat_emoji_tip.csb` 引用 `_box_black_gold.png` 并使用九宫格。原导入把贴图的宽装饰切成了边框。现在从同一贴图提取实际圆角、细棕边及不透明黑底，按录屏比例贴靠聊天栏左侧。三列表情与内部滚动条都裁剪在底板内。三个新的图像和对应源文件哈希由竞技场导入脚本和清单维护。

## 聊天与房间生命周期

原服务端本机发送请求耗时 4 毫秒。原客户端丢弃发送回执，并将查询成员和聊天串联后等待 2 秒。使用相同服务模拟旧的接收循环测得 1,911 毫秒。当前用写入成功后的消息回执立即显示本端，接收端用带超时的长轮询。MySQL 提交成功后，当前服务实例唤醒对应房间的等待读取方。等待读取期间释放数据库连接。历史仍按数据库 ID 排序，发送回执不推进历史游标。服务在读者等待超时后也会刷新历史，支持断线恢复，原即时读取协议继续可用。客户端关闭房间时取消两个读循环。表情成功发送后关闭选择浮层，发送失败保留浮层。

服务端采用成员租约。正常点离房即时移除成员。直接退出程序、进程崩溃或网络中断由心跳租约兜底。活跃房间每 5 秒读取成员状态，刷新 60 秒租约，服务端限制同一成员的写频率。后台每 10 秒清理过期成员。仍有在线成员时由最早入场者接任房主，最后一人离场或过期则删除房间及聊天。过期审计与回收同一事务。迁移 005 给存量成员一个完整的恢复窗口。

更新既有环境时，先用现有服务迁移命令应用 `005_arena_room_member_lease.sql`，再替换服务端。客户端本轮仅修改 Arena 热更程序集及资源，适用既有 Foundation 母包兼容检查。聊天实时唤醒对更新后的客户端和服务端同时生效。

## 验证

- 真实本机 MySQL 服务端测试 243 项通过，覆盖房主到期、活跃访客续期、房主转移、最后成员删除、长轮询授权、唤醒、超时及取消。
- 本机旧服务确有遗留房间。迁移后约 61 秒由后台自动删除房间和成员，记录一次 `arena.room.expire`。测试主动离房在 16 毫秒内确认目录移除。终止本机测试房主的独立心跳进程后，在线访客在 58.359 秒接任。
- 本机双会话 HTTP 测五次，发送回执及接收读取在 5 至 14 毫秒完成。Unity 图形 PlayMode 7 项通过，最新一次发送端和接收端显示分别为 33 和 16 毫秒。原版代码在 1.25 秒的本端显示回归测试中失败。还验证了文本回执去重、两端表情收发、发送过快时保留浮层、头像资源引用及弹窗裁剪。
- 来源检查通过，覆盖 77 个 Arena 资源、27 个 Home 资源及 67 个聊天表情。Unity 1920×900 截图已与上述录屏对照。
- Windows x64 IL2CPP 0.1.4 本机开发包构建通过，并从内置 Foundation 包完成冷启动。房间双端交互使用 Unity 图形 PlayMode 验证。
- 外网聊天延迟、4K 和手机实机画面未测。运行用证据存于 D 盘项目的 `.artifacts/arena-room-reliability` 和 `.artifacts/arena-room-lease`。
