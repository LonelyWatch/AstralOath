# ADR 012：战斗表现时钟、夹攻交接与骨骼预备

日期：2026-11-13。状态：已实施；本机Editor验证与平台边界见[本轮交付记录](../../delivery/2026-11-13-battle-timing.md)。

## 背景

攻击开始时在主线程重新解析整份角色骨骼，实测首轮超过一秒；特效反复创建时重复解析。Cut-in 与舞台同钟并行使安洁莉卡 S3 的光柱前段在遮罩后已经播放完。夹攻又等待前一动作所有回位和粒子结束，造成不必要停顿。

## 决定

1. 权威 Battle 事件顺序与结果保持不变；本地表现只读已接受事件。源 STG 秒钟控制 ANI、CFX、HIT、位移和相机。Cut-in 独立消费真实经过时间，冻结舞台源时钟；音频原事件继续按其自身时间线播放。用户暂停则冻结本场表现和本场 FMOD，禁止使用全局 Time.timeScale 或 AudioListener.pause。
2. CUTIN 完成边不重复累计片长；等待只由实际 Cut-in 播放承担。跨帧步长必须在 cue、HIT、Cut-in 起止点切分。主动作角色骨骼由表现拥有时钟，不能再由 Update 额外推进。
3. 主攻击的最后 HIT 已显示且旧反馈清空后，允许夹攻开始。旧动作只负责恢复尾段与剩余特效，新动作独占镜头。相机从实际显示取景接手，CAM0/ZOOM1仍指原作者基准；普通后续回合等所有尾段清理完成。
4. 原始骨骼事件采用顺序读取，跳过无关 mesh/deform 数据。SkeletonPlayerSource 持有不可变解析结果，独立实例共享数据而不共享 Skeleton、AnimationState、皮肤选择、变形、事件队列、网格、材质或暂停状态。缓存随场景资源源对象释放，不用全局静态字典留住纹理。
5. 开战前 Prepare 当前阵容实际技能依赖和时序。接力演出共享本场只读源缓存；播放期间不再构建整份 JSON DOM 来查询动画事件或时长。

## 兼容与验收

Core骨骼桥接和Bootstrap音频新增能力属于AOT，需新母包。客户端表现改动不改服务器协议、伤害算法或战斗随机数。新母包后的兼容业务与资源仍按既有热更方式发布。

证据分三层：原始源字段；录像支持的解释；项目补偿规则。不能以录像某一帧推导所有角色的全部行为。具体取样、限制见 [安洁莉卡时序复核](../../delivery/2026-11-13-angelica-timing-reference.md)。
