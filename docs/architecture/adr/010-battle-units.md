# ADR 010 — 战斗单位定义、实例与站位

日期 2026-11-12。状态为已采用。

`BattleUnitDefinition` 保存身份、元素与初始形态，其子类为 `HeroDefinition` 和 `MonsterDefinition`。英雄定义引用成长模板与按角色配置的觉醒节点。`BattleUnitForm` 组合演出 ID 与技能 ID，以便同一身份配置不同形态。切换时的生命、Buff 和冷却继承由具体技能规则决定。

`BattleUnit.CreateHero` 和 `CreateMonster` 均生成同一种对局实例。实例持有独立 ID、队伍、槽位、面板和当前生命。两侧可各有 1–4 号槽，允许空位。阵型拒绝重复实例 ID 和重复占位，枚举顺序为我方、敌方，各侧从 1 到 4。Unity 负责把槽号映射到脚点。

小怪、精英和 Boss 共用怪物定义。遭遇提供 `MonsterRank`、等级和面板，可以为同一个怪物设置不同数值。阶段、免疫和特殊行动按遭遇或单位能力组合，避免因能力排列增加继承层。当前仅支持入场和写入已经结算的生命变化。回合、行动条、目标、技能、召唤、复活、形态切换及快照发布留在第三步接入。

Shared Battle 保持纯 C#。服务端用指定版本的内容生成权威实例，客户端根据快照和事件显示。怪物与形态的原作证据见[成长与战斗单位](../../development/battle-growth.md)。
