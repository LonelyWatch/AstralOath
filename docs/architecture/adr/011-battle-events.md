# ADR 011 — 权威战斗与技能事件

## 决策

共享 Battle 程序集执行回合、校验命令、应用技能变化并生成快照。Luban 效果行表达技能的顺序、阶段、操作、目标和参数。技能解析器对当前状态做私有推演，返回有序变化。对局先验证整批变化再应用。事件序号用于向客户端交付结果，命令序号与命令 ID 用于拒绝乱序及幂等重试。固定种子和接受命令序号决定随机序列。

采用纯 C# 的技能程序和类型化领域事件。Epic Gameplay Ability System 的技能、持久效果、表现提示分层适用于此处。项目在既有 .NET 与 Unity 程序集间共享运算，并让 Unity 的 STG 与 Spine 负责表现时间。动画播放、跳过或未收到帧事件不会改动权威状态。[Epic Gameplay Ability System](https://dev.epicgames.com/documentation/en-us/unreal-engine/understanding-the-unreal-engine-gameplay-ability-system)

## 对局边界

服务端持有阵容、内容版本、随机种子和当前状态。房间锁串行处理两侧输入。双人验证入口由服务端发座位凭据，客户端提供技能、目标和魂燃意图。事件续接按序号，超出留存窗口时换用最新快照。房间只保存在当前开发服务进程内。

扩展技能时先新增配表行，复用已有操作。新增通用效果时，补目标门禁、变化类型、应用规则和可重放测试。追加攻击、夹攻、反击和被动有独立来源字段。主动和被动共用技能程序。被动由触发阶段、条件和操作组成，优先新增配表行。统一目标策略由权威命令、AI 和客户端复用。状态变化包含来源和回合数，额外回合作为独立事件，并由对局在行动条选人前安排。规则行为或事件契约改变时同步客户端与服务端版本。按模式增加长期规则时，保持规则版本固定在开战，重新确认效果优先级。客户端发布走既有 HybridCLR 程序集清单，服务器按生成配置构建发布。
