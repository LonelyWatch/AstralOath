# ADR 016 统一窗口、交互反馈和操作留痕

状态：采用。记录日期 2026-11-14。

## 决策

- 扩展现有 Core `WindowCoordinator`，按 UI 根管理一个主页面和当前所属浮层。页面替换先关浮层，再取消旧页面。单次打开使用独立 `BindingScope`，异步失败只清理自身。`UIViewRegistry` 负责预制加载与实例，业务 Binder 负责输入行为和状态。
- Common `GameUiFeedback` 配在根 Canvas。触点扩散与 UI 音效在页面切换后仍可完成。原版音色按普通、确认、取消和返回设置，通用组件适配鼠标、触摸和键盘提交。表现组件无业务和网络依赖。
- 服务端业务审计跟随事务写入。选定的客户端语义事件经过身份、白名单、限流与去重后存入同一表。接口及留存边界见[业务操作留痕](../../development/operation-audit.md)。

## 取舍

沿用现有窗口协调器和资源注册表，减少每个 Binder 重复保存弹窗打开状态。优先用页面及一个浮层满足当前业务，后续出现真实多层模态需求再增加堆栈契约。集中式反馈可复用池，无需在每个预制配置一套 VFX 和临时音源。权威审计与客户端语义留痕各有触发来源，避免逐次操作强制网络往返。

Common/Core 和首场景的变化随新母包发布。数据库迁移先于新服务上线。已有模块按新增、改版时接入同一机制。
