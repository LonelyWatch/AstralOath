# ADR 008：离线双版本骨骼与独立角色实验室

- 状态：用户批准，2026-11-12 实施。
- 范围：首批 c1001、c1005、c1062，Unity Editor 与 Windows x64 IL2CPP。

## 决策与原因

保留原始 Spine 2.1.27 / 3.8.99 数据，分别使用官方 2.1.25 固定提交 `142e770e5b4b42395a3a0a68ff3c8a21ba2774eb` 和 3.8 固定提交 `8b4844bd4b193ba9e54487ed397a777993cbad56`。两套 C# 核心隔离命名空间与程序集，使用统一的项目骨骼接口。修改 JSON 版本号不能解决动画求值差异，因此不迁移为 4.2。

旧 Unity 插件不直接导入。项目通过两版官方核心计算骨骼与顶点，再由 Unity Mesh 桥接处理渲染。原始 SCSP/SCT 只转换容器/数据表示，不重新解释为另一版骨骼；未知引擎字段保留或明确报告。许可证、上游固定提交、校验值和适配补丁跟随本地包保存。

FMOD 2.03.15 使用用户提供的官方 Unity 包，固定托管与 Windows x64 原生版本；原始事件和日语音频表一起加载。语音随机行为交由原始事件处理。声音库在关联事件停止并释放后卸载。离线运行无需打开 Spine/FMOD 编辑器。

`CharacterPresentation` 作为可复用业务模块管理演出；`CharacterLab` 管理测试 UI；两者是 HybridCLR 程序集。双核心、Mesh 桥接、FMOD 桥接和稳定启动契约为 AOT。新增骨骼姿态查询等公共契约随本次母包发布；后续修改必须强更。

实验室使用独立 YooAsset 包和启动入口，构建配置不读取 Foundation 签名与发布基线。临时 HybridCLR、构建场景和 PlayerSettings 在成功/异常后恢复。测试包在本地包含所需资源，不依赖服务器、MySQL 或远程更新。

## 数据维护

角色显示、排序及中文文案以 Luban 表为编辑源；解析器维护导入目录与演出数据。每个角色独立目录，多角色共用资产集中存放。导入清单登记原始路径、源哈希、转换器报告、输出哈希和依赖。原始 `D:/sevenepic` 只读；重复导入不重建已有 GUID。

首轮图像对照保留 RGBA32 原始解码结果；SCT 已预乘的 RGB 不重复处理。大 PNG、声音 bank 与原生 DLL 走 Git LFS。Android 压缩与原生桥接留待对应平台验收。

## 限制与验收

运行库解析、网格有限值、音频 DSP 输出、Editor/Player 运行和原作视觉对照是不同证据。未确认 STG 条件、锚点和动态参数不得静默跳过或标为一致；实验条件映射明确标识。播放不计算战斗结果。首批样本不代表全部 E7 资源兼容。

国际服版本追踪只由用户显式触发，本决策不创建后台跟踪或自动升级。

操作见 `docs/development/character-lab.md`，执行结果见 `docs/plans/2026-11-12-character-lab.md`。
