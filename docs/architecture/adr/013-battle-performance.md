# ADR 013：战斗性能测量与场景资源复用

- 日期：2026-11-13
- 状态：采纳

## 问题

战斗预览启动时为重复站位重新解析同一骨骼，版本探测又先建立完整 JSON DOM。仅测演出 Begin 函数遗漏输入提交、延迟特效、音频和渲染，也无法区分 Unity 编辑器设备扫描与游戏主线程耗时。

## 决定

1. 不可变骨骼解析数据按场景、骨骼/atlas/贴图资源身份与 pageName 复用；活动角色持有租约，最后一个角色禁用时清除条目。失败释放、场景隔离、SubsystemRegistration 重置均为契约。姿态、换肤、动画轨道、事件队列、Mesh 和材质仍归每个播放器所有，不共享可变播放状态。未来新增 scale、PMA 等可配置输入时必须进入键，不能依赖角色 ID。
2. 版本探测使用已有 Newtonsoft 的 token reader，只读取明确的顶层头信息；官方核心仍完整解析正文，完整结果版本必须与探测版本一致才发布缓存，拒绝重复头覆盖导致的错选。第三方运行库不因此升级或修改。
3. 保留 `Astral.Battle.Start/Frame/Submit`、`Astral.Audio.*` Profiler 标记。统计默认关闭，按测量窗口开启，原始最大帧、平台、后端、采样单位及不可用指标必须记录；未知或不可用指标不得填 0 伪装通过。
4. 启动、真实 UI 技能选择加目标命令、演出全程分别测量。采样包括首次、重复、终局重开；不能只反射调用 Present，也不能只报预热后的函数均值。实际规则接受的 Action 必须与测量声称的技能一致。
5. 增加独立 Windows Mono 诊断包，用于排除 EditorLoop/USB 扫描影响。仅构建时定义 `ASTRAL_BATTLE_PERFORMANCE`，临时设置必须恢复，输出隔离于正式发布、签名、YooAsset/HybridCLR 母包记录。它不能代替正式 IL2CPP/HybridCLR 包或 Android 设备验收。
6. 编辑器、进程启动、runtime ready、可操作帧、重开准备分开统计，全部原始帧保留。自然出现的环境卡顿如 USB 枚举也记录，不删除异常帧美化结果；环境根因通过日志相互印证。

## 代价与边界

共享源延长不可变解析数据到最后一个活动角色释放；重复角色减少解析和内存，但首个独特角色仍需加载完整数据。新增缓存不得跨场景无限存活。Mono 诊断只覆盖当前导入内容，不能推断所有 E7 角色或所有机器都已流畅。

## 验证

使用源身份/独立播放/释放/错误重试测试、版本类型与冲突头测试、GC.Alloc 阳性控制、完整 EditMode/PlayMode 及真实 Windows 诊断包。数据与命令见[当次性能报告](../../delivery/2026-11-13-battle-performance.md)。
