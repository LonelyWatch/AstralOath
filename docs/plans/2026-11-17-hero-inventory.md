## 名词和边界

英雄模板决定名称、初始星级、元素、职业和图像。英雄实例是玩家在区服内拥有的一只英雄，实例 ID 唯一；同名或同模板可拥有多只，各占一格。背包英雄列表按实例显示，项目既有选禁和战斗模板目录独立保留。本期不实现召唤、出售、经验、升星、换装或神器逻辑。

区服沿用「不凋零回忆」（`undying-memory`）。当前区服每个玩家默认容量 1000。正式账号及开发访客各发放一次拉斯（c1001，3 星）、梅赛德丝（c1005，4 星）和安洁莉卡（c1062，4 星），初始等级 1。正式账号重新登录沿用已有角色；访客仍使用独立访客会话。访客身份不按昵称合并。

## 服务端和数据库

- 新增迁移 010。区服背包头以 player_id、realm_id 为主键，保存容量。英雄表以 instance_id 为独立主键，保存归属、template_id、实例等级、星级及取得顺序；template_id 不唯一，建立归属和顺序索引。设定数值范围和外键，初始发放在事务内用背包头的唯一键与并发锁保证幂等。既有账号首次进入区服或查看背包补发同一组。后续获得英雄的写操作必须锁定相应背包头并检查余量。
- `GET /api/inventory/heroes` 复用既有区服 Bearer 校验，从认证结果取玩家 ID，并使用当前服务区服。客户端不提供 owner，不接受冒充其他账号读取。成功返回 `{capacity, used, heroes:[{instanceId, templateId, level, stars}]}`，列表有稳定顺序。未授权返回 401，数据库错误按现有机制返回 503。
- 延续账号邮箱验证、用户名/邮箱登录与单次选服身份。数据库只存随机盐、派生摘要和迭代参数，现有 PBKDF2-HMAC-SHA256 为 600,000 次，使用固定时间比较。会话只存摘要，校验码与令牌不进入应用日志或审计正文。密码哈希设计参照 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。本次补真实数据库证明和会话访问回归。
- 当前版本仅提供玩家读取接口。初始英雄发放由服务端内部事务负责，不开放客户端发放方法。数据库迁移先在本机测试库验收，服务端独立发布。复用 0.1.19 的稳定入口及会话，客户端改动放在已登记的热更业务程序集。

## 实施与验收

1. 服务端先写回归，覆盖密码摘要与盐、未登录、三名初始英雄、重复选服和并发不重复发放、双账号隔离及同模板两个实例。补迁移、账号选服初始化和读取接口。
2. 客户端使用现有主页预制体、窗口协调器及 GameText / GameButton。更多菜单和背包按钮各打开相应页面，独立 View/Binder 负责界面和加载生命周期。两页通过同一会话和读取接口取得数据。装备/神器只切换空页，列表按实例 ID 选择，显示实际容量。对较大列表重用可见行，避免为 1000 项一次性创建全部控件。
3. 用真实 MySQL 验证登录到背包和会话隔离，以不同宽高比的 Unity 图形测试核对两入口、两种布局、分类及同名实例。通过后检查签名热更、服务端兼容及正常启动路径。文档记录实测、未测项目和命令。
