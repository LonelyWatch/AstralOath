# 通用预制体 Binder 与 UIView 改造

> 执行方式：subagent-driven-development。用户本轮已经指定目标形态，直接实施并验证；不改变 Lua 业务层、服务端或已确认的插件选型。

## 需求与设计

预制体不再挂业务 View MonoBehaviour，只保留通用 BindingMap。普通 C# UIView 子类重写 PrefabPath（YooAsset 地址），统一注册表记录类型和路径，通过 IAssetService 加载、实例化并把生命周期交给 BindingScope。FoundationView 迁移为 UIView，Lua Binder 和 DemoWindow 保持业务职责。

BindingMap Inspector 每项固定一行：Key、对象引用、该对象的组件/类型选择、删除；不使用数组或条目的折叠展示。支持 GameObject 和 Component，保留原有序列化字段 entries/key/component，旧引用不丢失。缺失、重复 key、越界引用可定位并阻止运行。

Hierarchy 在 Prefab Stage 内，或普通场景中已有 BindingMap 管辖的对象行右侧显示 + / −。添加时使用最近的 Binder；Prefab Stage 尚无 Binder 时在预制体根节点创建一个。默认选常用 GameButton/GameText，其次 RectTransform/Transform；Inspector 可更换为 GameObject 或其他组件。重复对象不重复添加，同名 key 自动加后缀；减号移除该对象的绑定。支持 Undo/Redo、预制体持久化、缺失引用和嵌套 Binder，不为无关场景对象显示控件。

- Unity 2022.3.62f3、UGUI/TMP、YooAsset/xLua 版本不变；Common 不引用业务模块。
- 不覆盖 D 盘已有未跟踪 Content.meta、Bundles；源码先在现有 C 盘 worktree 的 codex/binder-view 实施。
- 不修改原始解包目录，不顺带实现配表/分包/服务器控制台。
- 不强制 Play 模式跳场景。现有 FoundationDemo 演示完成迁移并说明入口。
- 元文件 GUID 保留；生成场景/预制体在隔离副本生成并同步。

## 重点验收

业务 View 不在 prefab/scene 上作为组件；注册的 PrefabPath 确实用于加载。关闭/取消期间迟到的资源不得创建残留 UI。Hierarchy 不跨最近 Binder 修改引用。Undo/Redo 与 prefab 保存后引用稳定。重复 key、缺失脚本或对象应给出可操作错误，窄 Inspector 不把行变成折叠层级。
