# 普通装备强化与本轮交付

用户要求普通装备实际升级、主副属性与概率核对、右上角 `+X`、仅满级红底、原强化声音，并在验收后打包。此次不改已决定的 400 格神器容量或母包/热更架构。规则与通用验收文档、战斗力资料为本批独立交付项。

已选择性、只读解析原包 `itemenhance`、`equip_stat`、`equip_item` 等相关表；源身份、哈希、记录数和解析校验保留于 `.artifacts/equipment-enhancement-research/source-files.json`。`item_equip_upgrade` 是再炼表，不能误当普通 +0 至 +15 强化。原表字段必须与录像样本及官方公告交叉核对，未知执行语义不能仅凭列名认定。

概率以 STOVE 官方公告 [7902683](https://page.onstove.com/epicseven/global/view/7902683) 为依据，保存实际 API 正文及表图。词条种类等概率选择不等于其增量整数均匀分布；尤其速度和重复整数值必须保留权重。资料原发布日期、更新日和正文适用日分别记录，不能将国际服新增功能静默升级进本项目。

## 实施边界

- Shared 保持纯 C#；配置源为唯一编辑入口，生产快照通过工具生成。正式强化与旧开发 GM 近似配方区别记录，不以简化公式宣称还原。
- 服务器负责经验、等级、主属性、逐个 +3 里程碑的词条、金币和材料。账号锁、版本检查、幂等回执、扣费、更新和审计同事务；丢响应重试不得重掷。非法/跨账号/不足/满级必须回滚。
- 客户端新增普通 `EquipmentEnhancement` / `EquipmentEnhancementBinder`；页面由所属协调器以独立 `BindingScope` 管理。预览不是结算，动画不发奖励。入口返回应保留原英雄/装备选择，穿戴装备升级后同步面板。
- 通用 `NotificationBadge` 保存原橙/红底，根据当前上限切换；复用卡片必须从 +15 还原到 +3/+0/通知红点。神器有突破上限，不能把普通装备 +15 写死到全部物品。
- 普通强化材料选择、清空、自动登记、成功及取消按录像编排；素材、声音事件、持续时间和取消淡出分别核对。缺参考的魔力强化执行、再炼及修改词条不当作已实现。

## 验收行为

1. 先保存旧代码/预制与缺失入口证据；角标回归先红，旧预制对 +3 错用红色通知底必须失败。
2. 权威规则检查主曲线非线性尾段、+3/6/9/12/15 恰好一次词条事件、品质解锁时机、加权随机边界、经验加成/取整、一次跨多档与满级。
3. 真实隔离 MySQL 检查扣费与材料、经验持久化、重试原结果、并发/版本冲突、余额不足回滚、两账号隔离及已穿面板。
4. 图形检查英雄/背包入口、未选/选材/数量弹窗/自动登记/忙碌/结果/返回；1080p、4K 与调整窗口。声音和特效连续过程单独给出实际通过或未验证结论。
5. 逐项列原版实际效果、修改前、修改后、文件位置与未完成原因。文档/公式任务以原文与数据复算对照，视听不适用，不制造素材证据。
6. 当前已分发 0.1.25 / R35 缺 11 月 23 日 Common/Bootstrap 音频淡出 AOT 改动，本次角标接口也涉及 Common，交付须新 Windows IL2CPP 最小母包与匹配签名内容。检查包完整性、真实启动/更新/退出重开及缓存复用后再称可玩包通过；不部署生产。
