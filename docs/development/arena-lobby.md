# 主界面与竞技场模拟战

## 本机使用

1. 配置本地 MySQL 连接串后，在仓库根目录执行 `dotnet run --project Server/Host -- migrate`，再执行 `dotnet run --project Server/Host`。开发环境与运行账户权限见[服务端说明](../../Server/README.md)。
2. Unity 使用 **Tools → 游戏主页 → 打开启动场景** 后点击 Play。右侧 **竞技场** 直接进入模拟战目录。开发默认连接 `http://localhost:7728`；可通过 `ASTRAL_FOUNDATION_URL` 或场景 Bootstrap 的 Base Url 指定 HTTPS 服务器。
3. 目录可滚动、筛选、搜索及手动刷新，默认人数降序。搜索浮层保留至主动取消或打开其他浮层，输入框需主动点击。创建时输入房名、选择规则，按需启用四位密码和参与者聊天。其他玩家使用独立客户端刷新后可发现房间并入场。
4. 房间右侧只显示竞技场频道。按规则显示聊天许可，当前房主和第二名参与者显示在对阵两侧，其余参与者在下方列表。正常离开会移除成员，最后一名离开清理房间。
5. 进入「基本」房间后，房主可从顶部的盾牌和预禁按钮打开设置，把每边预禁人数设为 0 至 3，或开关第三手禁用保护。参战席资料下的 FIRST PICK 勾选决定先手。顶部最左的开战规则是独立选项。两席就绪后由房主开始。见[联机选禁与入场](arena-draft.md)。

当前游客名称由本机生成，`ASTRAL_ARENA_PLAYER_NAME` 可为本机测试指定名称，竞技场游客共用拉斯默认头像。会话令牌在进程内存中维护，同一次运行可经当前房间接口恢复。正常离房由服务端立即处理。断网或强制结束进程后，服务端按最近活动保留约一分钟的恢复窗口。成员过期后，若房主不在，房间交给最早入场的在线成员。最后一人过期后房间及聊天从数据库清理。更新服务前需通过现有迁移入口应用 `005_arena_room_member_lease.sql`。「基本」规则接入联机选禁，与服务端同步发布时需应用 `006_arena_draft.sql` 和 `007_arena_preban_three.sql`。正式账号仍待接入。

房间设置入口按本地用户录像 1:49–2:20 和 `pvplive_lounge.csb` 核对。新建房默认每边预禁 2 人、房主先手、保护开启，修改由服务端保存并同步给两席。

## 资源与布局

基准是用户提供的前七张截图和本地 `pack-15-r4262`。创建房间弹窗的状态、关闭提示和按钮校准见[弹窗复核](../delivery/2026-11-14-arena-create-dialog.md)。目录、房间、入场密码和点击反馈的原版对照见[目录与房间复核](../delivery/2026-11-14-arena-directory-room-feedback.md)。主界面沿用 `lobby_bg3` 及 c5009 原版模型。房间庭院用原地图集中的树、花、地面、城墙和天空图层组合；位置按截图校准。目录、弹窗、规则图、VS、通用按钮和头像均使用已存在的资源。未接入的其他主页功能入口保持省略。房间主题、美术比例与手机画面可继续实机对照。

编辑器重新生成入口为 **Tools → 游戏主页 → 生成主页和模拟战**。它重建主页与模拟战预制体、选禁素材目录及启动场景，原 CSB 只作为资源与排版证据。手动编辑布局前先保留预制体变更。Canvas 使用 1920×1080 参考、高度匹配和安全区；目录、规则卡、成员和聊天各自拥有滚动裁剪。

Foundation 包和既有冷启动验签链继续使用。新增 Home、Arena 业务程序集。更新稳定启动契约、Unity 首场景和 AOT 立绘桥需要重新构建母包。发布需同步服务端迁移。

## 验证

### 目录刷新（2026-11-21）

首次打开目录、战后返回时先查询当前房间。服务端确认仍在房内时直接进入该房；确认已离开后再读取目录。已经显示过目录时，手动点「更新目录」会并发读取当前房间及筛选后的目录。当前房间始终决定去向，即使列表未返回也能回房。关页会取消未完成的读取。连续点击共用按钮的在途保护，操作留痕异步上报。

页面在同一个位置复用房间行。仅房主、房名、规则、密码状态或人数等显示数据变化时更新控件。刷新相同的空目录也不再强制整个 Canvas 立即布局。手动刷新保留滚动位置，主动搜索或更改筛选时从第一行开始。

实测使用 Unity 2022.3.62f3 的无图形 PlayMode，计时从调用目录 Binder 或点击按钮至重新可操作，不含登录和预制体加载。两组数据分别测量本机请求及网络等待影响：

- 本机 `127.0.0.1:7728`、实际访客会话和 MySQL 空目录。两个冷进程首次打开分别为改前 125 ms、改后 109 ms；连续手动刷新五次分别为 6/2/2/2/2 ms 与 2/1/1/2/2 ms。本机未复现秒级等待，这些单机冷开数据包含创建访客会话的开销。
- 在真实目录预制体上为每个读取注入 120 ms 延迟，保持审计响应未完成。旧版首次打开 345 ms、手动刷新 256 ms；改后首次打开 302 ms、手动刷新 122 ms。冷开保留串行回房检查。手动刷新的两个读取从串行变为重叠。回归入口为 `ArenaDirectoryRefreshTests.ManualRefreshReusesRowsAndChecksMembershipWhileFetchingTheList`，本机日志和结果在 `.artifacts/arena-directory-review/`。

- 服务端使用实际 MySQL 8.4，238 项通过，覆盖两会话、刷新、设密加入、聊天权限、服务重启、容量与并发末席。
- Common EditMode 14 项通过，覆盖实际通用预制体、复用状态和 UI 创建菜单。下述图形 PlayMode 同时覆盖点击音效和鼠标／触屏长按。
- Unity 主页启动、四个预制体 Binder 与 Foundation 收集地址通过生成校验。图形 PlayMode 5 项通过，覆盖双会话创建、九房间溢出与滚动、名称搜索、错误密码、正确入场、双向聊天和离开。验证可用 `ASTRAL_ARENA_TEST_URL=http://127.0.0.1:7728` 后运行 `Tools/Invoke-Unity.ps1 -Mode PlayMode -Graphics -TestFilter AstralOath.Client.Tests.GameHomeArenaTests`。
- Unity 图形截图检查主页 1920×900、1600×900、1200×900，以及宽屏目录、创建和房间。手机实机和带刘海设备尚未验证。
- Windows x64 IL2CPP 开发母包通过构建和默认主页冷启动，日志有 `ASTRAL_CODE_BOOT_OK release=builtin recovered=False`。本次的两端房间流程在 Unity 图形 PlayMode 运行。开发包支持本机明文连接，发布客户端需配置 HTTPS 服务地址。

本次录像复核、原版音效和泛光来源、窗口约定以及本机测试范围见[录像对照交付](../delivery/2026-11-14-arena-recording.md)。更新服务时应用 `003_game_operation_audit.sql`，权限及打点语义见[操作留痕](operation-audit.md)。

房间聊天收到服务端确认后立即显示自己的消息，其他客户端通过长轮询接收。成员状态与消息读取独立运行。房间表情使用第 `004_arena_chat_stickers.sql` 号迁移。Windows 包默认可缩放小窗，主页右上角或 F11 切换显示模式。录像对照、表情素材和平台验证见[本轮复核](../delivery/2026-11-14-arena-ui-fidelity.md)。
