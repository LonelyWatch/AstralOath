# 战斗源演出接入规范

本规范供后续角色、皮肤和舞台接入使用。原始资源与转换器的契约见[角色资源导入](character-asset-import.md)，权威事件与试玩入口见[战斗执行](battle-execution.md)。当前样本的原图、数值和录像证据见[镜头源数据复核](../delivery/2026-11-13-camera-source-audit.md)。

## 版本与依赖闭包

- 以同一角色形态、皮肤和版本的模型、技能 STG 与明确关联的 timeline 为根。按源引用递归收集 CFX、粒子、骨骼、图集、纹理、镜头动画、Cut-in 和音频。旧模型与同名或相近技能的资源要分别登记。拉斯当前使用 `model/ras.scsp` 与 `c_ras_skill_*.stg`。旧 `model/rasselclare.timeline` 配套 `rasselclare.scsp`，不作为当前 Ras 图的补充。
- 保存 STG 的 entities、connections、entrypoint、eventlisteners，保持动画、骨骼、事件和资源地址的原始标识。通过角色导入工具生成图与清单，校验源路径、哈希、转换版本和已有 GUID。原始目录只读，导入范围限于已批准的依赖闭包。
- 对源 `SHAKE` 及已声明的 timeline shake 收集 `camera/<name>.scsp`。镜头专用骨骼可以没有图集或纹理，需能实例化并取到 `camera` 骨骼。保留源时长与 `timeScale`。镜头 X 按角色固定朝向镜像，平移与震动在同帧合成，动作终止时清空震动。原始 `powerX/powerY/type` 的倍率语义需用实帧验证。
- 每个资产准备入口校验已执行的节点及依赖。导入时的缺依赖、版本冲突或无效时序属于错误。运行时对无法解释的节点、边、锚点、格式或范围给出一次可定位的诊断，保留原参数和技能标识。使用已有近似分支时注明适用范围和未验证字段。

## 图和播放时间

- 从 ENTRY 遍历可达节点，保留同一时间的连接顺序。STG 与 timeline 的时长、延迟、淡变使用毫秒，Spine 事件与 Cut-in 转换帧使用秒。集中换算到播放时钟。对当前支持的连接，缺省 `when` 或 0 在前节点完成后调度，1 在前节点开始时调度，再叠加边的 delay。零时长节点先应用状态再进入同刻后继。
- `ONEVENT` 按实际动画名与骨骼事件名匹配，`ANI_SCOPE` 同时读取 from 和 to。已见的 style2 MOVE 用跳起事件作开始，采用显式时长或起落事件跨度。其他后继沿自身开始或完成边执行。大时间步跨过多个 cue 时按实际边界推进，保证 Cut-in、CFX 与震动的时间相位。
- 当前有证据的 `when=2` 用于把 `SINE_VALUE` 绑定到父 `PPEFFECT(sprite_blur)` 的 `u_range`。子节点与父同时开始，保留各自时长。原 shader 的方向、样本上限、分辨率、三角权重与 ratio 用源公式。当前预览使用半正弦叠加包络和世界画面合成。原引擎的相位函数、默认参数和渲染范围仍需录像或运行时证据。对其他 `when=2` 组合先记录证据。
- BGSHOW、DARK、BGHATCH、Cut-in、后处理和 LAYOUT 分别管理可见性和生命期。恢复时覆盖动作完成、中断、重开、场景卸载。记录源淡变时间与当前执行差异。只播放同一时间轴要求的效果，避免给同名技能叠加另一版本的演出。

## 镜头、位移与锚点

- 分别记录地图作者坐标、STG 偏移、Spine 资产比例、实际角色缩放和屏幕投影。当前作者舞台采用 1280×720 左下原点，世界单位每作者像素 .015，当前 STG 偏移及 Spine 导入使用 .01。比例与镜像以字段的坐标空间为准，按同一规则验证多名角色与双方阵容。
- CAM 聚焦使用移动后的表现锚点，取景保存基准脚点相对视口的垂直构图，再叠加源偏移。地图可见时按视口半宽、半高约束显示取景，让实际底图覆盖画面。隐藏地图的全屏阶段保留源请求倍率与镜头路径。相机请求缩放和受覆盖限制后的实际缩放各自保存，恢复时还原基准镜头与远景变换。
- 按节点类型解释 location。当前 CAM 使用施法者、主要目标、双方中点或目标群中心，MOVE 11 取施法者槽位，MOVE 16 接近主要目标，CFX 6 对每个受影响单位执行，CFX 42 使用群中心。保留 `locationParam` 的 shadow/root 等语义。验证不同槽位和不同目标数量时的锚点及跟随方式，未知 location 先保留诊断。
- 角色的固定朝向决定局部 X 偏移、CFX 旋转和镜头摇动的镜像。向目标接近时根据真实位置求行进方向，自疗和同方治疗使用固定角色朝向。MOVE 操作角色表现子节点，影子沿地面轨迹，纵向跳弧只作用于角色。只改变显示的 LAYOUT 需要恢复参与单位和旁观者的 Renderer 状态，权威槽位继续由战斗快照管理。
- 当前 MOVE 曲线、`power`、`h` 和有限 LAYOUT `self_x/away_x/fade` 的原引擎语义仍待验证。新增样本同时覆盖普通接近、原地纵向位移、有限布局和离屏布局。需要固定偏移的差异优先查找共有坐标或来源问题。

## CFX 和命中反馈

- 每个Spine primitive的显式 `ani` 优先，缺省才使用 animation、idle、首个可播动画；选择和寿命计算必须使用同一规则。显式名称不存在要诊断并拒绝该实例，不能悄悄改用默认片段。存在性与时长分开判断：有效0秒静态姿态可由ani或延迟action选择，按显式lifeTime保持；不能因时长为0报不存在，也不凭空延长未声明的寿命。延迟actions单独按delay执行，只计入实际存在的动画；如原 `Fire` 在对应骨骼中不存在，记录未映射语义，不凭名称猜造动画或延长寿命。
- 有限DARK的duration为开始渐退时间，fadeOut单独追加；负duration保持到STOP。舞台释放和图完成时间使用同一规则。该解释经安洁莉卡连续帧及跨角色源字段核对；不能自动套用到CUTIN或BGHATCH，源accel仍未验证。

- CFX 的完成时间和资源释放共享同一时钟。优先取显式 lifeTime，再取 Spine 动画和延迟动作的有效时间，或粒子的最晚启动、末次发射和最大粒子寿命。无限连续发射必须由明示生命周期控制，缺少原时长时记录项目的限时回退。依赖 CFX 完成的图边随实际执行模型推进。保留同一时间的层级、叠加和跟随关系。
- 共享战斗逻辑及服务端提供已接受的动作、目标、伤害、治疗、反击、夹攻、击倒和最后状态。客户端用 STG 的 HIT、骨骼事件及画面完成时间安排表现，动画回调只更新视觉。命中粒子的随机采样使用独立的表现随机数。客户端放映流程不写入结算或奖励。
- 当前图中可达 HIT 的时间排序并对同刻去重，同一时点可以播放多个目标。当前九技能缺少每击权重字段，已有总伤害按时点均分，差额由累计整数分配吸收。最后一段累计值等于权威总量，血条、浮字和击倒时机消费这些视觉段。命中权重、额外追击来源与原作计数需要权威事件或原版证据，录像的 11 Hits 不能作为把普通 STG 的三个节点扩成 11 个的依据。

## 新角色验收

1. 固定角色形态、技能版本、资源哈希、舞台与阵型。记录原版录像的发布日期、片段时间、可见技能名和版本证据。
2. 用真实 STG、Spine 事件和依赖资产做 EditMode 测试，覆盖源 HIT、零时长、并行、跨 cue 大时间步和动作中断。新节点先保留能失败的回归，再实现和复验。
3. 带图形运行 PlayMode，采集动作启动、接近、主命中、Cut-in 前后、摇镜峰值、后处理与回位。检查足部构图、森林边界、双方镜像、群组锚点、透明混合、资源释放、HUD 与声音。
4. 复核至少一条普通地图近战、一条全屏隐藏地图、一条范围或治疗。将项目截图和原版连续帧按技能事件对齐。自动测试、目标平台播放与原版画面对照分别登记，注明实际执行范围和仍缺的证据。

## Cut-in、接力和准备阶段（2026-11-13 修订）

- CUTIN节点必须传递curtain_color与curtain_opacity。缺省黑色/不透明，显式0保持透明；幕布覆盖世界与常规HUD，位于原帧之下和暂停交互之下，排除sprite_blur世界采集。幕布跟随Cut-in墙钟同生共灭，中断也释放，不修改演员Renderer。缺省解释由首批录像支持，显式源参数始终优先。
- 区分墙钟与舞台源时钟：CUTIN播放时只推进帧，不推进舞台ANI/CFX/MOVE/CAM/DARK和HIT反馈。结束恢复源时钟；CUTIN完成连接在源时钟上不重复增加帧时长。用户Pause同时冻结两类视觉时钟、本场FMOD及输入，Resume不重播。源时钟进度要从播放器读取，不能用墙钟累加替代。
- 角色骨骼在受演出控制期间只被同一分段时钟推进一次。Update仅负责未被演出拥有的待机/受击等；不能在同帧又按unscaledDeltaTime推进一次。
- 夹攻在前动作最后HIT已呈现后启动，旧演员继续回位；旧舞台释放镜头所有权，新舞台继承真实显示取景与原作者基准。相机当前实际值与源请求值不同的情况必须覆盖地图边界测试。
- 开场准备实际阵容依赖，缓存骨骼原文的事件/动画时长和不可变解析数据。每个source有明确资源所有者，退出释放，不静态持有资产；同source实例的pose/skin/deform/事件/mesh仍必须隔离。日志区分首次冷启动、准备耗时、准备后首次攻击和重复攻击。不能把Unity Mono无效的分配计数0解释成零分配。
- 新角色验收增加Cut-in前后连续帧、最后HIT→夹攻开始→两人回位、地图约束后的连续CAM/ZOOM、攻击入口及最慢Tick测量。重要结果随任务即时入文档，来源不明的近似留明确边界。

设计见[ADR012](../architecture/adr/012-battle-presentation-clock.md)；视频和原字段见[安洁莉卡时钟复核](../delivery/2026-11-13-angelica-timing-reference.md)。


## 信息条、速度线与姿态衔接（2026-11-13）

- 普通攻击、技能镜头、BGHATCH和舞台特效不得主动隐藏 `Unit Status`（生命、等级与状态）。技能组/Burn的输入可见性单独管理。真正全屏的 CUTIN 由既有幕布/帧排序自然覆盖信息条；不能通过提前关掉全部 HUD 代替遮挡，暂停交互仍在最上层。
- 移植源 shader 时，同时核对原始 PNG 是否为直通/预乘 alpha、引擎上传纹理时的处理、shader 输出编码、混合因子与顶点淡变。不能只复制 fragment 公式。`bg_hatch_1/2/3` 的亮度主要储存在 alpha；透明白像素必须不发亮。原图、GUID、源 STG 颜色与速度保持不变，具体证据见[背景审计](../delivery/2026-11-13-hatch-alpha-audit.md)。
- 动作结束时不能把演员直接重置为另一套待机首姿态。先核对当前骨骼尾姿态与目标待机；原生 `b_idle_ready` 只有起点契合时才可采用，不能按名字给所有技能统一插入。过渡还必须检查目标未键骨骼、附件、绘制序和 FFD 的最终状态；首帧连续不等于正确收敛。
- 回归需包括真实受击与技能尾帧、动画轨已自动结束后的延迟返回、暂停/中断、重复返回、两个共享源实例的状态隔离。新增角色遵守同一规则，不用角色 ID 或世界位置补偿掩盖骨骼问题。项目补偿用的过渡时长必须标注为待原版连续帧确认，不能声称来自原始 STG。

## 信息条与死亡生命周期（2026-11-13）

- 信息条在骨骼和镜头更新后投影top，使用含父骨变换的骨架空间位置，再转Unity世界；Actor/镜头缩放共同决定屏幕比例，文字不因朝向倒转。不能只读相对父骨X/Y，不能用动态Bounds或角色ID偏移补偿。
- 普通条十等分、50%较高线来自2026-11-08官方录像测量；不泛化为每1000HP或Boss/盾规则。刻度跨整个槽，主HP与原dhp尾层各自插值，重复快照不重置、治疗可打断、暂停不推进。
- 权威UnitDefeated决定死亡，末击驱动视觉黑化/淡出；身体和粒子尾完成分别管理，不为等烟雾阻塞全部回合，也不提前停用槽位截断尾迹。动画回调禁止结算；暂停、同帧复活、重开、卸载均回归。
- 开场准备本场死亡粒子，仅控制当前骨骼Renderer的PropertyBlock和影子。Dispose自有对象立即脱离后延迟销毁。源纹理PMA、混合与颜色字段须配套验证；项目时长、默认死亡变体映射标明证据边界。
- 每次改动同步近期视频时间点、实际原作帧、源清单、失败回归、实景截图与最终结果，不能用几项绿测代替画面对照。[当前记录](../delivery/2026-11-13-health-death-presentation.md)。

- 自定义具体UGUI Graphic须显式提供CanvasRenderer；验收必须包含真正PreRender提交的mesh/material/texture及实帧，不能只手动调用OnPopulateMesh。
- particle.colorBlends按time、A、R、G、B解释；不能把这个顺序泛化到CFX或其他颜色字段。原键的alpha、RGB与PMA输入/输出同时检查，并用Burn和死亡两个真实来源做回归。详见[死亡审计](../delivery/2026-11-13-death-source-audit.md)。
