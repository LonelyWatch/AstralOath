## 已证实的问题与工程边界

- 七人召唤页原用`HeroRosterPortrait(renderSize:480, animated:false)`；只有animated分支按屏幕适配，导致480²被放大。实际复核88/88.5/92/98秒可见呼吸/眨眼，七人页改为实时idle及按投影像素分配RT，窗口变化重绘原骨骼，隐藏暂停、关页释放。其他静态列表继续480预算，不一并升到4K。源纹理审计未发现这七人源图被全局缩小；旧压缩JPG属于未引用的旧伊赛丽亚循环，不是本页模糊根因。
- 邮件说明源RGB180，43实际255。第一轮预先`.linear`的候选实际渲染117，已判失败；Canvas已进行转换，应只录入源颜色一次。按钮Regular400仍被`.28`白描边撑粗，先用`.06`候选并实际测色/看图，不仅检查材质字段。
- 现有聊天仅属于竞技场房间，接口校验成员资格，不能借它假装公共频道。新增独立公共聊天，使用现有MySQL、Bearer身份、游标/NDJSON模式，不加外部基础设施。
- `arena_player.display_name`允许历史重名。新增改名不能直接给旧列加唯一索引；必须保留旧记录、以稳定playerId识别，并为新改名认领建立唯一约束及事务检查。
- 客户端PlayerProfile/ChannelChat独立业务模块，Foundation组合，Home接回调，不让Common引用业务。公共未完成提示素材预制放Common，普通View/Binder由既有热更Foundation组装，避免新增稳定AOT类型；预制只挂BindingMap和基础控件，独立WindowCoordinator/BindingScope允许通知盖住更多菜单、资料盖住聊天后分别返回原窗口。
