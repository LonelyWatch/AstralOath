# 项目通用规范

适用于新功能、修复、工具、配置和资源。下文区分“已有设施”和“开发要求”，不能把要求写成未经验证的实现保证。入口和现状见[文档入口](../README.md)、[当前状态](../project-status.md)。

## 目录、依赖与版本

- 客户端 `Assets/Game`；服务端 `Server/Host` / `Server/Tests` / `Server/Ops`；纯C#共享 `Shared/com.astraloath.shared/Runtime`。数据库、网络、Unity不得进入共享战斗逻辑。
- Bootstrap 负责启动与组装，Core 负责契约/基础能力，Common 负责可复用组件；业务在 Modules/<Module>，Common 不反向依赖 Modules。
- 模块默认 `Scripts/Configs/Editor/Tests/Res/{Atlas,Prefab,Textures,Sounds,Animations,Materials}`，需要时添加 Effects 等目录。用 Tools/New-Module.ps1 创建，禁止覆盖已有模块；模块 README 必须描述职责、依赖、公开接口、配置/资源地址、生命周期和验收。
- 运行时、Editor、Tests 的 asmdef 按职责隔离；测试源码必须有测试程序集，不能直接落进业务编译。新增UI模块需引用 TMP/UGUI，不能依赖可传递引用的假设。
- 新热更业务 asmdef 设 autoReferenced=false，并登记适用更新清单；Foundation 与 CharacterLab 使用不同清单/入口。AOT 不静态引用热更实现。
- 工具链、Unity和依赖版本锁定；只在明确升级任务中修改锁文件、来源和补丁记录，并复验。禁止编辑Unity生成csproj或直接改第三方代码来绕过错误。

## 生命周期、代码与通用服务

- 优先显式依赖注入和实例所有权；单例必须说明谁创建/释放、Domain Reload与测试如何重置，不以全局状态串联业务模块。
- 所有异步操作有取消、超时和生命周期；Unity对象操作回到主线程。关闭窗口先取消，再解绑事件、停止动画、释放资源句柄；对象池归还恢复状态，旧异步结果不能写入新实例。
- BindingScope 统一管理订阅/句柄/动画；禁止 async void 业务入口，Unity事件适配处必须捕获异常、处理取消并保证释放。
- 通用接口留在 Core/Common，业务实现留模块；涉及协议/配置/共享契约变更先列兼容影响，再实现。事件表示事实，不用不透明全局消息总线绕过依赖。
- 日志可定位模块、操作、版本和关联ID；不得记录口令/令牌/私钥/完整生产连接串。错误不得静默吞掉或用占位成功冒充真实成功。

## UI 与交互

### 接到需求先核对效果图

- 先沿玩家的操作路径列出本次涉及的页面、区域和可见状态。以换装为例，背包选中物品、英雄选装备、换下已穿物品分别查图。一个页面的效果图只能说明画面中实际可见的内容。
- 制作前实际打开参考，在模块文档或实施方案标明对应入口、状态、图片路径或视频时间段，以及能从画面确认的布局和交互。优先查用户指定的目标版本实录和已有项目参考，再查原版客户端内置教学图或官方实机资料。注明已知语言、版本与遮挡，涉及动效时查连续帧。在回复中给用户可打开的关键图。
- 已有界面素材时，先逐区域建立源节点、贴图及页面状态的对应关系。按参考复用其底纹、阴影、边框、装饰、九宫格与透明度，不以纯色或自行生成的面板替代已有资源。找不到某处素材须记录具体区域和已查路径，不能把替代块当作还原完成。2026-11-24 的授权与复核记录见 [界面原素材](ui-material-reference.md)。
- 从原界面移植遮罩/半透明底时，同时核对纹理alpha、节点opacity、颜色、父级覆盖及项目色彩空间。原sRGB合成覆盖率不能直接当Unity Linear的Image.color.a；按用途合成并转换，保留原图及用途副本来源，不能按RGB阈值删除黑底来近似“透明”。至少用同背景和静态白图标区域测透射，再实际对图。规则来自11/28主页、提示和聊天的失败复核，详见[本轮方案](../plans/2026-11-28-home-social-visual-fix.md)。
- 对图时标出多个位置重复出现的部件，例如物品卡、属性行、槽位和角标。已有通用预制时直接嵌套；需要新增的共用部件在一份预制上配置层级、锚点和显示状态。页面分别负责摆放、筛选及操作，在各实际入口验收同一组件。
- 缺少某个状态、两个版本布局冲突或录像没拍到关键过程时，具体向用户索要哪一步的截图、连续录像或时间点。拿到依据再拼该区域或编排该段动画。零散图标、布局节点、文字攻略与项目自己的截图可辅助定位，不能单独作为原版成品效果图。
- 验收时用相同入口、状态和可比宽高比复拍，逐项记录同异。功能回归与画面对照分别记录，尚缺参考的状态列入待核对项。

### 控件、布局与生命周期

- 离屏生成预制时父节点可能宽高均为零。固定比例缩略图的 `AspectRatioFitter` 先设布局模式，再设已知宽高比。验收嵌套实例时同时检查保存的比例为有限正数，并在页面截图中确认物品可见。单独渲染物品卡无法发现父预制将尺寸算成零的问题。
- 动态立绘和角色演出使用 RenderTexture 时，以 Canvas 最终投影到屏幕上的像素宽高核对采样密度，并验证窗口尺寸变化。排查模糊时分别记录源图集附件像素、离屏尺寸与上屏尺寸。头像横卡按源图比例、源锚点和裁切区布局，用不同宽度的头像复核。

- Foo.prefab 对应普通 Foo.cs / Foo : UIBaseView 与 FooBinder.cs，大小写一致，不额外加 View 后缀。View 重写 PrefabPath；稳定资源地址不随文件重命名自动变化。
- 预制体用通用 BindingMap 保存引用；业务 View/Binder 不作为组件。View只维护显示，C# Binder负责界面业务/订阅，领域规则放业务服务。
- 固定页面的控件在编辑器中排好并保存到页面预制体。多处共用的装备槽、角标等组件使用嵌套预制体，在父预制体上配置槽位图和位置。打开页面时绑定数据、替换图片、更新可见性。按持有数量变化的列表复用预制行模板。
- 一组控件共用一个局部坐标系与缩放基准。验收装备槽时检查底板、符号、物品与角标的相对位置。验收滑条时以牌面实色边界测量露出量和行距，覆盖横屏、窄屏及运行中调整窗口。
- 道具信息弹板、装备详情卡等固定内容卡使用固定设计宽高与锚点，不随视口比例分别拉伸宽、高；分辨率适配交给Canvas统一等比缩放。窄窗口先在安全区内调整位置，确实容纳不下时整体等比缩小，不能压扁背景、图片或文字。长文在固定正文区域滚动，不以描述行数撑大外框。全屏页面及明确需要伸展的容器另按原版设计处理。验收须在相同窗口高度、不同宽度以及不同高度下分别核对卡片逻辑尺寸和长宽比。
- 项目文本用 GameText : TextMeshProUGUI，按钮用 GameButton : Button；不可再叠加原版同类组件。右键 UI 创建完整控件，Add Component只添加组件。官方Inspector排版/导航继续使用。
- 界面按 Canvas 布局。按钮底板、图标、头像、立绘、页背景、血条等 Sprite 默认用 UGUI Image。精灵有切片边框的面板和按钮可用 Sliced，头像和立绘按设计保比例。原始 Texture 或 RenderTexture 用 RawImage（如选禁的阵型模型投影和切门画面）。确需自定义网格或遮罩时用合适的 Canvas Graphic。
- 场景按世界坐标布置。SpriteRenderer 适用于以世界相机、深度或排序、遮挡和场景特效为依据的精灵，例如战场远景、地层和角色地面阴影。混合显示按每一层的用途选组件。世界空间 Canvas 上的 UI 也沿用 UGUI 控件。角色头顶的血条、等级、Buff 和目标按钮属于 HUD，在 Canvas 内渲染，世界挂点由显示代码投影。骨骼和粒子按演出需要使用对应的渲染组件。
- GameText.Bind 不覆盖作者排版；实际界面文案使用稳定 key。新建菜单占位不是业务文案。GameButton.Bind提供异步点击去重与取消，奖励/扣费还必须由服务器事务与幂等保障。
- 通用动画通过 IAnimationService / DOTween 管理，池化复用和关闭必须终止并复位；动画回调不得结算战斗或发放奖励。
- 播放中的音频因切页、取消或销毁而中断时，默认以 0.20 秒平滑降低音量，再停止播放并释放音源及资源句柄。淡出使用独立于页面和游戏时间缩放的生命周期，关闭页面应立即释放视觉与输入。维护原音量及混音分组，复用音源时避免淡出任务串到下一段。自然播完及应用退出可直接清理。
- 修改BindingMap后检查空引用、重复key、对象归属、生成映射和Prefab保存；移动资产带原.meta，已有GUID不得重建。

## 全面屏、平板、Android、PC

- 横屏设计，1920×1080参考尺寸；背景按视觉需要铺满，关键交互放Safe Area。使用锚点、布局组件和滚动，不写死物理屏幕像素。
- 优先在预制体或生成器里用 RectTransform 的 anchor、pivot 和相对偏移表达布局。边缘控件锚到相应容器边缘，背景在容器内拉伸或按比例裁切，列表交给布局与滚动组件。固定尺寸用设计参考单位。代码只补标准布局无法表达的情况，例如极端宽高比重排、软键盘避让、世界坐标投影或按视口更新 RenderTexture。窗口断点在视口、容器或安全区变化时重算，世界跟随按画面更新，避免为了单个控件逐帧重建整个 Canvas。
- SafeAreaLayout已按Screen.safeArea与窗口尺寸更新；它只应挂在与Canvas归一化坐标一致的安全区容器，不能任意嵌套后假定结果相同。
- CanvasScaler需要按界面选择并记录策略：Foundation为MatchWidthOrHeight/0.5，CharacterLab为Expand。右键自动补的Canvas是Unity默认设置，制作正式界面时必须配置参考尺寸和安全区。
- Windows 客户端开启 Unity Player 的后台运行，失焦不暂停界面、计时或网络。PlayerSettings 变更随下一次完整安装包交付，验收使用常规启动的 Player 切换焦点，避免使用会强制开启后台运行的冒烟入口。
- 平板4:3、常规16:9、长屏、带缺口Android、PC缩放/窗口尺寸变化都需验收。宽屏可扩展背景/列表，窄屏保持按钮可点、文字可读；需要断点布局时由模块明确实现并记录。
- PC测试鼠标/滚轮/键盘导航和焦点，Android测试触摸、防误触、返回/前后台恢复。不要让Hover成为唯一提示或把鼠标行为当成触屏验收。
- Android目标ARM64/IL2CPP，ASTC和ETC2分开产出；Windows x64/IL2CPP。最低Android API/target API与工具链以ProjectSettings和锁定文档为准；平台能力差异要有显式路径。

## 图片、图集、音频与角色资产

- 原始解包 D:/sevenepic 只读；只导入已开发模块及依赖，来源/哈希/转换器版本/依赖闭包必须记录。角色每人独立目录，共享依赖集中维护。
- 现有导入器为 Assets/Game/Editor/GameAssetImportRules.cs，默认作用于 Assets/Game；UI默认关闭Read/Write和Mipmap，常规纹理最大2048、平台压缩。源图和显示需求决定最终尺寸，不能未经检查统一降质。
- Android ASTC/ETC2独立构建；Windows按透明度/内容选择平台格式。文字、小图标、渐变、PMA边缘必须目检，不能只看文件体积。
- 大立绘、全屏门和叠加特效的取景尺寸与离屏绘制尺寸分别设定。前者沿用原图坐标，后者按控件的实际屏幕像素分配，超过平台预算时等比缩小。验收至少覆盖 1080p、4K 和窗口缩放，检查实际 RenderTexture、显存及原帧裁图。拼帧动画记录每帧有效像素和最终投影大小，整页图集或录像文件的「4K」标签不能代替这项测量。[签名实包核对](../delivery/2026-11-22-client-image-quality.md)
- 骨骼图集/动画WebP等已有明确不压缩或尺寸例外时保留；Importer UserData 精确等于 AstralOath.ImportOverride 的覆盖标记 需记录用途和验收。例外不等于所有新资源默认RGBA32。
- 图集按窗口/模块/生命周期拆分，避免一个常驻大图集装全游戏；共享资源有唯一归属，资源地址稳定。大型二进制用Git LFS，不把Library、构建产物或完整源解包提交。
- 短音效、短语音、长语音/音乐分别制定压缩和加载策略；现有Unity导入器按目录选择加载方式。FMOD bank按事件引用持有并释放，不能事件仍播放就卸载共享bank。
- SCSP/SCT、Spine版本、曲线语义、atlas旋转/裁边/PMA必须遵守[角色导入规则](character-asset-import.md)；未知字段和依赖明确失败/诊断，不硬改版本号或逐角色打补丁掩盖通用转换错误。

## 多语言与配表

- 文本locale与语音locale独立，当前zh-Hans与ja；点分稳定key（各段小写、数字、下划线）、格式占位符、字体回退和缺字日志是通用契约。新增语言需字体、排版、文本长度和音频资源一起验收。
- 每张表只有一个权威编辑源。当前本地Luban CSV/XML为实际入口，未接Google Sheets同步；未来换编辑器必须定义唯一来源和可复现导出。
- schema/源表改后运行 Generate.ps1 -VerifyAccessors -SyncClient；提交源、生成器及必要客户端快照。生成物禁止手改；CI -CheckClient拒绝快照失配。
- 配置ID、枚举、引用、范围、资源地址都需校验。破坏性schema变更要版本化并审计客户端/服务端；数值变化不能擅自改变已开始战斗的配置版本。

## 服务端、数据与通信

本机游戏 API 统一使用 7728 端口。服务端监听 `127.0.0.1:7728`，编辑器场景与 Windows 游戏入口访问 `http://localhost:7728`。内容下载与 MySQL 使用各自的端口。需要并发运行多个测试服务时显式指定隔离端口。

- .NET模块化单体，MySQL8.4/InnoDB；初始不引入Redis/消息集群。SQL参数化、异步取消/超时、事务与幂等；同一请求ID不同内容必须拒绝。
- 迁移脚本不可修改已应用历史，执行前备份，使用迁移账户与最小权限运行账户。恢复演练使用空隔离库；不可用资源回滚指针回滚数据库。
- 2026-11-28用户明确：正式版前无需兼容旧测试数据，可以为更合理的数据库方案废弃旧数据。可在明确的新版本重建schema/初始化基线并同步协议、测试和文档，不为旧数据额外保留劣质字段或兼容分支；不得原地改写已应用迁移后假称仍为原版本。当前改动若不需要数据模型变化，不为落实该权限而无目的清库。正式发布后的数据保留和迁移策略另行制定。
- 权威战斗/货币/奖励在服务端；客户端表现不作为结算依据。Protobuf源在Tools/Protocol，生成共享C#；字段编号不得复用，破坏兼容时维护更新。
- 生产HTTPS/WSS必须验证证书，不跳过TLS校验；明文仅限开发loopback。现有WebSocket为开发回显，不代表正式对战连接、鉴权或断线重连已完成。
- 游戏API、内容分发、安装包分发是不同职责；连接串/私钥/证书只在本地私密配置或部署环境。容量用压测确认，不能以目标100人保证2核4GB始终足够。

## 更新、构建与发布

- 用户只说「打包」时，默认核对目标平台已分发母包的兼容性，然后构建签名热更包。需要更换启动代码、启动资源、信任配置、原生库、平台或不兼容协议时，或者没有可复用归档时，才构建最小强更包。
- 最小安装包包含启动、登录、选服、强热更、资源验证和恢复所需的稳定代码及资源。角色、场景、战斗界面和活动主题随 YooAsset 签名发布。热更完成并校验后提示退出游戏，退出后重开启用新内容。发布步骤与边界见[热更与强更构建](hot-update.md)。

- 兼容C#业务、配置、资源通过签名发布清单/YooAsset热更；冷启动激活。程序集不在同一进程卸载替换。失败恢复是下次进程行为。
- AOT/Core/Common/启动器、原生库、裁剪能力或不兼容契约改变要重建母包；原母包归档、平台/架构、AOT元数据必须对应，不混用Windows/Android/压缩变体。
- 客户端Battle可热更与服务端同源发布是两件事。规则、配置或协议不兼容时维护协调，服务端程序集不通过客户端HybridCLR/YooAsset更新。
- 资源先上传不可变版本，再切换发布入口；签名私钥不交客户端。拒绝坏签名/哈希、错误母包、低磁盘、部分下载和路径越界，并验证恢复。
- 强更安装包构建与服务器强制升级是两种能力；当前缺失策略/准入闭环，详见[核对结果](../delivery/2026-11-12-foundation-reaudit.md)。更新UI可以后做，但准入规则必须前后一致。
- 任何已验收结论都记录代码基线、母包、平台、命令和结果。普通CI/Editor通过不能替代实际Player/设备；不自动部署生产。

## 任务完成后的通用验收

本节适用于每次任务，包括界面、逻辑、资料研究、规范及文档调整；记录使用[任务与交接模板](task-template.md)。先由执行者实际比对并处理发现的问题，再整理给用户。不能把用户第一次查看当作代理自己的验收，也不能仅凭编译通过、文件存在或其他 Agent 的完成消息确认效果无误。

- 每个入口、区域、交互状态或行为用例分别列出「原版实际效果／目标依据」「修改前效果」「修改后效果」及自行比对结论。原版必须来自实际查看的目标版本或已确认的需求/契约，不能用项目旧图冒充；注明来源、版本/形态、录像时间段和已知倍速。画面采用可比视口、比例和状态，动作及特效保留连续过程；账号、数值、语言或版本差异单独说明，不宣称不同输入逐像素一致。
- 修改前证据应在动手前保存并注明基线提交。未留修前画面/音轨、参考缺失或版本冲突时，明确记录缺失及影响；不能重建示意图、合成音轨或修改后截图冒充历史实机。新增功能没有修改前状态时，写明此前入口/能力不存在并给出基线证据。纯逻辑、研究或文档任务分别使用原行为/权威资料、前后数据或原文与 diff；视听项写「不适用」及具体理由，不制造截图或音效。
- 涉及音效、语音、动画或特效时，同时列出原版、修改前及修改后的可听/可播放证据。标出同一触发操作、事件/素材标识、时间段、持续时长、起止/取消/淡出及重叠播放状态；记录播放倍速、音量设置等比较条件。执行者必须实际试听音效、观看特效连续过程；波形、资源已绑定、事件已触发或静态帧只能证明各自事实，不能替代听感与时序验收。未能试听/播放则如实列为未验收。
- 每项分开标注「实际通过／失败／环境阻塞／未执行」，记录复现输入、动作、预期与实测、命令、环境、退出码、日志及原始证据位置。功能测试、画面、音效、特效、Editor 与 Player 分别下结论；失败或缺口可先报告，但不能称全部完成或效果无误。修正比对发现的问题后重验受影响状态，再交付相应最终证据。
- 列出本次新增、修改、重命名和删除的文件，说明用途及准确位置。面向用户的清单使用可打开的绝对路径；文本/代码按需给行号，预制、二进制或资源给层级/BindingMap key、GUID、资源地址或来源清单。生成文件同时注明编辑入口和生成命令；证据文件也列保存位置。不得用「已改界面」或仅贴提交哈希代替文件清单。
- 每个未完成或未验证项写明具体内容、原因、影响、尚需资料/环境及下一步最小操作，区分参考不足、规则未核、能力未实现、环境失败和明确不在本次范围。不得以「后续优化」代替原因，也不能把素材存在当作功能和效果已完成。
- 图录、音视频与报告应对应代码提交、配置/资源版本和实测包；有包时记录平台、母包及内容版本。最终代码或资源再变化，应复验受影响部分，不能引用旧图充当新包验收。明确区分源码已提交、Editor 已验证、包已构建、实际安装已验证和已分发；未打包/发布就写明未打包/发布。
- 对照证据和清单保存于 D 盘项目资料目录，并同步模块文档及变更日志中的入口；向用户给出关键对照、文件位置、实际结果和未完成原因，不能只留在聊天或只给不可定位的数量。原始截图/录像/音轨、日志及提交/包标识保留可追溯关系，遵守素材授权、敏感信息和构建产物不入库的约定。

## 文档、AI与Git

- 默认在main主工作区修改、中文提交并推送origin/main；不强推，不覆盖用户已有改动。开启新会话先读现行入口，不从旧计划恢复过时架构。
- 功能/配置/资源/构建行为改变，完成一个可验收小步就更新对应模块README和变更日志；不能等整个系统做完才补文档。重要约定写ADR，状态变化更新project-status。
- 排查中的重要原因、源字段解释、性能测量、视频时间戳、取舍与未验证差异随结果立即入文档；新会话不能依赖聊天记录恢复这些结论。事实、录像支持的推断、项目回退策略分别说明。
- 提交前执行文档同步检查、适用测试和差异检查；CI复核。机械检查只保证相应文件同批修改，语义正确由审查负责。
- 交接记录目标、完成内容、未完成项、文件、命令、结果、环境限制、临时进程及下一步；没有验证写未验证，阻塞写具体原因。
- 国际服版本追踪只由用户显式发起；禁止后台轮询、定时跟踪、自动升级依赖。Unity MCP仅用于Editor，命令行入口必须可用。

## 本机存储与演出维护

项目资料与临时产物遵守[D盘规则](local-storage.md)，工具入口统一初始化 ProjectEnvironment，不新增独立的C盘缓存路径。源驱动战斗演出遵守[通用规则](battle-source-presentation.md)：角色ID不参与临时修正、节点未知必须诊断、视觉命中不得结算权威伤害。

角色验收从战斗与实验室的正常入口取帧。按同一形态检查局部动画时钟、施法者与受术者的动作、镜头父骨变换、画幅和复位。每处共性偏差留一个能区分修正前后结果的原型技能，并用其他角色复测。记录跨版本录像的可见差异。[逐角色的帧与镜头验收](battle-source-presentation.md#逐角色的帧与镜头验收)

## 性能测量与资源复用

遵守 [ADR 013](../architecture/adr/013-battle-performance.md)。性能修复先建立可复现的完整输入/启动基线，再验证首次、重复、释放后重建；报告 P95/P99、最大帧、样本数、GC 与采样平台，不能用仅 Begin/Present 耗时代替整段体验。Profiler 指标不可用时明确标记，不以 0 计为通过。编辑器与独立程序分别测试，保留原始慢帧并说明外部阻塞证据。

共享缓存必须有资源身份、生命周期所有者、失败回收与最后释放路径；缓存不可变数据，播放实例保持独立。临时诊断包与正式签名发布/母包归档隔离，临时设置用 finally 恢复。新增角色不允许通过角色 ID 分支规避性能或资源格式问题。

自建 TMP 位图字体除了可见字符，还必须验证主字体保留字符 U+005F：指向真实像素且有非零下划线厚度。保持原生数字 UV/advance，不通过关闭警告或空字形掩盖兼容问题。
## 界面生命周期与操作留痕

- 新场景的正式页面和浮层使用 `WindowCoordinator` 和独立作用域。预制加载、控件反馈和 Binder 的业务操作沿用各自通用设施。[UI 接入](ui-binder.md)
- 在模块设计和审查中显式评估操作留痕。权威操作随服务端事务记录，纯客户端操作按业务语义白名单上报。屏幕点击、表单原文、凭据和聊天文本不得进入留痕。[打点规则](operation-audit.md)
