# AI 任务与交接模板

复制到当前任务记录，按实际证据填写。完成项只记录实际观察，不能把计划、文件存在或编译通过写成运行验收。

## 目标和验收

- 用户目标、已确定的选型、目标分支及明确不在本次范围的功能。
- 可观察的验收行为：输入、动作、预期显示/事件/持久化结果和取消/失败路径。
- 当前版本、配置 schema、协议及资源版本；是否需要维护更新。

## 修改边界

- 文件所有权：每个 Agent 的独占目录，唯一 Unity 操作者与 Git 提交者。
- 相关模块的公开接口、依赖方向、生命周期和释放责任。
- 唯一配表编辑源、生成命令、生成快照路径、资源来源/哈希与依赖闭包。
- 新决策写入 ADR；涉及用户已决定的基础设施变更先明确提出。

## 验证记录

- 回归触发与修复前失败证据；具体命令、运行环境、退出码及结果路径。
- .NET、真实 MySQL、Unity EditMode/PlayMode、目标构建、实际 Player/设备分别记录。
- 检查取消、重复调用、超时、销毁/复用、订阅和资源释放；更新检查签名、文件、空间和回滚。
- 独立审查发现、处理结论、针对修复的复验，未验证项及原因。

## 交接与发布

- 源码提交哈希、远端分支、启动/复现命令、日志与产物位置。
- 本机启动的测试进程及清理责任；不把临时凭据或私钥写入交接。
- 仍需用户监督的具体行为与输入素材、缺失内容、下一步最小验收。
- 国际服追踪只响应用户的明确指令；普通开发 CI 不进行外服采集或生产部署。


## 文档同步（提交前填写）

- 变更日志条目及对应模块README更新位置。
- 接口/配置/资源/操作方式变化；对应规范或操作说明的位置。
- 当前状态是否改变；project-status更新或无需更新的具体理由。
- ADR是否需要；用户既有选型是否保留。
- `node Tools/check-docs.mjs --staged`结果；推送后CI运行链接和结果。

## 中断时的最小交接

- 主工作区、分支、基线、已提交/未提交文件、Agent所有权。
- 最后成功的命令和证据；正在运行的进程/测试及清理责任。
- 当前失败原因、下一条可执行命令、尚缺的信息/外部环境。
