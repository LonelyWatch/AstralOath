# 模拟战选禁与入场

从 GameHome 进入竞技场，创建「基本」房间。默认每边预禁 2 人、房主先手、第三手禁用保护开启。预禁可设为 0、1 或 2，双方都拥有当前服务器战斗目录里的英雄。第二个独立客户端入房后，VS 两席就绪，房主可点开始战斗，两个席位自动进入选禁。

- 预先禁用同时进行。选择满房间人数上限后提交；双方提交后公开结果。上限为 0 时直接进入选人。
- 选人顺序从先手开始为 1／2／2／2／2／1，双方各选五人。单选窗口 30 秒，双选两手共用 60 秒。已经选用或预禁的英雄会锁定。
- 最终禁用同时进行。每边选择一个对手英雄，开启禁用保护时第三手不可禁。双方确认后显示被禁印章。
- 阵型使用剩余四人。点击两个站位交换，再按战斗开始确认。站位按战斗场景的前、下、上、后顺序发送，阵型界面的实际位置与战斗一致。双方确认后闸门关合遮住加载，打开后角色从上方落地，完成 IGNITION 后开放本方回合操作。

## 服务端与发布

选禁与对局权威在服务端。事务锁定同一个房间。客户端按版本提交，使用请求 ID 去重，并限定为当前选禁 ID 或对局 ID。不同席位的同阶段提交可并行，禁名和站位在对手端按阶段公开。超时由当前两席的读取或操作推进，服务端从合法候选中选择；退出或席位活动过期会取消该次流程。战斗命令和配置摘要用于重连与回放。普通房间成员可以留在房间，观战入口尚未实现。

开发运行前应用迁移 `006_arena_draft.sql`，重新启动服务。正式客户端需新 Foundation 母包，因为 BattleScene 成为第二个内置场景，入场资源随母包。BP 窗口与角色素材目录随 Foundation YooAsset 包发布，进入 BP 时才读取角色预览资源。新增英雄时同步 BattleScene 战斗目录和原版卡面素材，再运行 `Tools/游戏主页/生成主页和模拟战` 生成对应目录和预制体。其他规则仍可保存和加入房间，联机开局目前只开放「基本」。实机录像对照图须经用户确认后才构建客户端安装包。

## 验收和待核对

MySQL 集成 244 项通过，Unity 图形 PlayMode 覆盖房间、选禁、双方独立会话、四个具体站位、银蓝闸门、八名角色落地与战斗事件同步。截图来自 Unity 编辑器实机，横屏包含 16:9 与 21:9。局内已接入服务端权威回合截止时间及原版红蓝圆形计时格：双方演出（含回合入场）就绪后开表，超时执行合法默认动作。30 秒为可配置项目策略，尚未核实为录像全部模式的原作时长。最新界面、IGNITION 和回合计时验收见[画面修订记录](../delivery/2026-11-15-draft-visual-revision.md)。阵型配置、禁用揭示和开场时序仍待用户截图审核。
