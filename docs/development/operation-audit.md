# 业务操作留痕

新系统接入前在模块说明列出需要排查、追溯或统计的动作，写明触发时机、记录字段、归属和调用端。动作名使用稳定的英文业务键。界面上的点击反馈独立于留痕，打开弹窗或提交搜索这类关键界面操作使用语义事件。

## 权威写入

创建、入场、离场、发言由 Arena 服务端在业务写入的同一 MySQL 事务中追加审计。审计采用服务器身份、目标房间 ID、操作名和 UTC 时间。重复入场、重复离场和失败请求不会生成成功记录。最后成员离开后仍可按房间 ID 查到审计。断线成员被回收时，在同一事务记录 `arena.room.expire`，使用过期成员及房间 ID。正常心跳不写审计。

其他模块按需复用 `Server/Host/Foundation/OperationAudit.cs`，使用受控动作名、服务端签发的身份和实体 ID。审计值仅记录标识和结果需要的字段。密码、令牌、聊天文本、搜索词、账号联系方式和自由输入不进入审计表。高频轮询、滑动、每次点击和无实质变化的重复提交不打点。

## 客户端语义事件

`POST /api/arena/telemetry` 接受 `eventId`（32 位十六进制 GUID）和白名单动作 `directory_refresh`、`directory_filter`、`directory_search`、`create_dialog_open`。服务端从 Bearer 会话解析身份、按会话和事件 ID 去重，并限制每次请求大小和频率。客户端保持少量并发，离开应用取消，请求失败不影响界面和实际业务结果。相同 ID 的重试只记一次。客户端事件仅用于定位交互路径，不能当作权威操作结果。

应用 MySQL 迁移 `003_game_operation_audit.sql`。运行账号仅需对审计表的 INSERT 权限，查看留痕使用独立只读账号。上线前由服务维护确定留存期限、备份和清理方式。当前该表随数据库备份，未配置自动清理。
