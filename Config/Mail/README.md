# 游戏内邮件目录

`catalog.json` 是邮件配置的唯一编辑源。Host以 `AstralOath.MailCatalog` 嵌入源JSON，加载时检查schema/rulesVersion、普通/GM两种行为、唯一ID、引用、数量、纯文本长度、嵌套循环、深度与实际可入账资源。客户端从鉴权的 `GET /api/mail/catalog` 读安全目录。修改目录需要重新发布Host；不存在另一份客户端奖励配置。

`letterTypes` 独立于 `templates.purpose`：`standard` 可批领，`gm` 必须逐封收信。维护、活动、开发测试和通知是用途，不从发件人名称推断行为。标题最多120字符，正文最多8000字符，最多20个附件，有效期1–90天，单项数量1–1000000，独立英雄/神器/装备单附件最多10件，展开总奖励不超过1000万、独立实例不超过100件。这些是项目安全规则，不冒称原作上限。

可入账种类为真实召唤钱包currency、通用材料material、同材料账本的energy、英雄hero、神器artifact、配置内训练装备equipment及确定性bundle。发送预览校验实际存在的英雄、神器和装备，并把名称、头像、展开奖励、星级及装备属性冻结。礼包不是随机或选一；`attachments` 保留外层，`rewards` 为展开的实际发奖规格。多个同材料先合并，再写同一内部operation下的唯一流水。配置下架不使已发邮件重新查目录或重抽属性。

`gm_gift` 的 `presentation=gmGift` 支持原片同封两阶段：领取权威成功后先封面，再展示2/5/5奖励；切换阶段不再次请求或再次入账。`cover=gm_gift` 是稳定表现标识，实际美术映射归Mail模块；特殊封面原目录ID尚待确认，不能据此声称已还原具体图像。

行动力是既有 `inventory_artifact_material` 内受控键 `energy`，初始0，项目naturalCap默认360，绝对安全上限10亿。邮件可越过naturalCap，GM设置与正常summary重读同一份余额。这轮不实现自然回复、等级影响或关卡消耗；360不是对原作全部账号上限的断言。

变更后运行服务端Mail测试（隔离MySQL配置与命令见 [服务端](../../Server/README.md)）。目录非法、循环、乘法溢出、null附件、缺失发件人和已冻结奖励在下架后仍可领取均有回归。资源图标仅为稳定表现标识，目录通过不等于客户端图像、动画或声音通过。
