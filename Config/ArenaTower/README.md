# 普通竞技场固定关卡

服务端直接读取 [catalog.json](catalog.json)。每个关卡独立配置防守英雄、等级、附加面板和首通征服点。调整这一份 JSON 后重新发布 Host 即可改变后续开战参数。采集程序只写历史观察表，不会改动已设计的关卡。

## 防守阵容来源

2026-11-28 读取了韩国社区作者在 **2020-07-11** 发布的国际服普通竞技场百强名单。榜单提供名次、积分、四人名单和各英雄的总出场数。同分可能并列，以文章出现顺序为唯一行号。100 份观察实际有 85 种不计位置的四人组合，共 400 个位置、42 个英雄形态。发布页给出的每种英雄出场数均与逐行汇总一致。样本记录的是当日高分段，没有提供玩家装备、速度、技能等级和精确阵形位置。[公开名单](https://m.hungryapp.co.kr/bbs/bbs_view.php?bcode=epicseven&pid=125785)

匿名观察表保存原韩文阵容与榜单分数，不存玩家昵称。运行时表的 `sourceRow` 对应观察表的 `row`；`sourceSlots` 是实际出战英雄在原帖该行中的一基序号。例：第 1 关使用原表第 93 行首位冒险家拉斯，战斗中以项目已有的普通拉斯出战。所有 100 行各引用一次。没有新增未实现英雄的战斗技能。[原始观察](defenses-global-2020-07-11.json) · [关卡与段位](catalog.json)

使用项目 Python 执行 `Tools/Arena/ImportTowerDefenses.py` 重新获取公开名单，也可传 `--html <已下载文件> --output <比对结果路径>` 复算。导入器同时校验行数、每队四人、队内无重复和作者的出场次数。匿名事实校验值为 `c3a75790b8e4d8d73d18d4dbcf873b5979136fd2f4d5e1f1b78c142833d67326`。本次下载的原页保存在 D 盘工作区 `.artifacts/arena-defense-data/hungryapp-m.html`。

## 项目难度

第 1–5 关各一人，等级均为 1；第 6–16 关两人，第 17–30 关三人，第 31 关起四人。前 20 关无装备加成。缩编的前 30 关合计减少 51 个出场位置，固定关卡实际配置 349 个位置。低关优先移除治疗或复活核心。首通发 5–40 征服点，首通全部 100 关合计 2,201 点。阵容、等级、奖励和成长节奏都是本项目的设计数值，未测得玩家实际通关率。

各阶段的敌人等级和每人装备等效固定加成如下。中间关卡的整数值已逐关写入配置，调整一关不会改变其他关。

| 通关目标 | 敌方等级 | 攻击 | 生命 | 防御 | 速度 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1–5 | 1 | 0 | 0 | 0 | 0 |
| 12 | 5 | 0 | 0 | 0 | 0 |
| 20 | 10 | 0 | 0 | 0 | 0 |
| 30 | 16 | 30 | 120 | 18 | 2 |
| 40 | 24 | 80 | 350 | 52 | 7 |

| 70 | 48 | 435 | 2,300 | 265 | 28 |

段位按最高通关数达到阈值时晋级。`bronze/silver/gold/master/challenger/champion/emperor/legend` 对应 **0、10、25、40、55、70、85、100** 关。历史样本积分只用于溯源。
